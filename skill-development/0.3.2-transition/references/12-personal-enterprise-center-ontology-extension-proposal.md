# 个人—企业—中心 Ontology 分层扩展研究提案

> 状态：Research Proposal / Experimental，不是正式标准。PDKS Ontology 0.2.1 在本轮保持冻结。

## 研究问题

个人数智底座、企业数智底座和中心数智底座需要共享部分语义，但三者的数据所有权、业务目的、管理责任、访问权限和数据粒度不同。若简单采用“个人继承企业、企业继承中心”的单向层级，容易造成数据权属混淆和未经授权的跨域传播。

暂定模型：

**共享语义核心 + 作用域扩展模块 + 独立治理/策略边界 + 显式映射与转换契约。**

## 四个逻辑部分

| 部分 | 职责 | 当前状态 |
|---|---|---|
| Shared Core | Person、Event、Source、Evidence、Assertion、Action、Knowledge、Time、Provenance 等通用语义 | 以现有 0.2.1 为研究基线 |
| Scope Extension | Personal / Enterprise / Center 各自扩展概念、关系和业务约束 | 研究提案 |
| Mapping Contract | 跨作用域映射、转换、脱敏、聚合、来源和损失说明 | 研究提案 |
| Governance & Policy | 数据主体、控制者、目的、授权、保留、访问与撤回 | 需要真实策略服务，当前未实现 |

## 三种作用域边界假设

### Personal Scope
以个人为数据主体和个人数据空间的主要控制者。个人工作事件、学习、思考、生活、关系、目标、能力和个人知识属于个人上下文。原始录音、私人对话和个人上下文默认不向组织共享。

### Enterprise Scope
以组织业务活动、项目、流程、角色、任务、决策、交付物和组织知识为核心。组织获得的是业务目的所需且经授权的工作信息，不因此拥有员工全部个人数据。同一事件可在个人与企业视角分别形成记录，二者通过来源与映射关联，不直接合并所有权。

### Center Scope
以跨组织、跨业务单元的标准、能力、指标、治理、协同和汇总认知为核心。优先消费经过授权的聚合、脱敏或标准化数据，不因处于更高管理层级就自动获得个人原始记录或企业全量明细。

## 关键原则

1. 共享概念不等于共享数据。
2. 映射不等于身份合并；不得仅因名称相同就使用 owl:sameAs。
3. 转换必须保留来源、目的、执行者、时间、规则版本和损失说明。
4. Ontology 描述治理语义，不自行授予授权。
5. 默认不外流；跨域流动必须经过目的限制、最小化、授权和审计。
6. 保留多视角，不把不同叙述压成唯一事实。
7. 撤回与删除必须考虑派生数据、索引、缓存和备份。

## 本轮不做

- 不新增正式 Ontology namespace、OWL 类或属性。
- 不创建真实跨域数据同步服务。
- 不实现企业/中心权限系统。
- 不把组织层级当成自动授权链。
- 不宣称该模型已在 ADS 或真实业务环境验证。

下一步应先用 2—3 个具体工作场景做概念验证，再决定是否进入独立 Ontology 扩展版本。

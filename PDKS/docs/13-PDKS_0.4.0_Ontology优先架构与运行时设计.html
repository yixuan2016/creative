01 / ARCHITECTURE DECISION

四个角色，不能混成一个系统

Ontology 定义数据意义；Schema 定义数据结构；Database 负责数据持久化；Agent 负责理解和使用数据。

本阶段不换掉 SQLite，也不急着部署图数据库。 Canonical JSON 是权威记录，RDF 是版本化、可重建的语义投影。先把语义和运行规则做扎实，再按规模引入独立图数据库。

02 / SYSTEM MAP

Ontology-first 数据运行架构

原始录音和文档单独存储；SQLite 保存引用、定位、哈希和治理元数据。RDF 投影可删除并从规范记录重建。

03 / MODULAR ONTOLOGY

从单体文件升级为模块化本体

CorePerson · Event · Entity · Assertion · Knowledge
Event工作、学习、思考、生活事件分类
Knowledge经验、方法、洞察、原则、案例
Personal Context角色、能力、目标、责任、偏好
Temporal发生、采集、记录、有效、截止时间
Provenance来源、证据、表达者、处理活动
GovernanceConsent、Access、Retention、Deletion
Agent RuntimeIntent、动作提案、审批、执行状态
OWL / RDFS、SKOS、PROV-O、OWL-Time、SHACL 各司其职。Ontology 描述授权语义，但真正的授权判定仍由运行时策略服务完成。
04 / SEMANTIC SAFETY

必须分开的六组概念

概念 A概念 B为什么不能混淆
Event：发生了什么Assertion：谁表达了什么观点不等于事实发生
Evidence：证据片段Knowledge：可复用知识证据是来源，知识是提炼结果
Personal Context：个人理解Owner-confirmed：本人确认AI 推断默认是候选，不自动成为事实
Intent：人的计划Agent Action Proposal：智能体动作提案计划不等于执行授权
Owner：数据所有者Creator / Speaker / Processor数据归属、记录创建、表达和处理是不同角色
Occurrence / CaptureRecord / Valid Time发生、采集、记录和有效时间不能混为一谈
05 / VERSIONING

本体升级，不强迫历史记录重写

Schema 0.1.x保持现有 JSON 记录兼容
Ontology 0.2.0升级语义模型与稳定术语
Runtime 0.4.0新增本体感知运行时
Migration Map旧术语等价映射与重投影

术语采用稳定命名空间 urn:pdks:ontology#；本体版本 IRI 为 urn:pdks:ontology:0.2。旧命名空间通过 owl:equivalentClass / owl:equivalentProperty 桥接。数据 ID、来源、证据和历史版本保持不变。

06 / LOCAL DATA MODEL

SQLite 保存什么，RDF 保存什么？

SQLite 表职责RDF 语义视图
pdks_objects规范 JSON 记录RDF Subject 与类型
pdks_object_versions不可变历史版本记录版本与时间语义
pdks_ontology_registry本体版本和哈希投影所用语义版本
pdks_triples可重建三元组投影类、属性、关系和证据边
pdks_owner_stateowner revision图按 owner 隔离
pdks_audit_log最小化操作审计审计摘要，不复制正文

为什么暂时不换图数据库？ 单人本地阶段先保证事务、可携带、低运维和可重建。需要大规模跨图推理、并发图查询或企业多租户时，再把 RDF 投影同步到独立图数据库。

07 / QUICK START

本地运行命令

python -m pip install -r requirements-dev.txt

# 本体信息
python prototype/pdks_ontology_cli.py ontology-info

# 校验 3 个示例场景
python prototype/pdks_ontology_cli.py validate \\
  --records-dir skills/pdks-personal-knowledge/examples/scenarios \\
  --strict-refs

# 初始化个人库
python prototype/pdks_ontology_cli.py init \\
  --db ./data/personal.sqlite3 --owner <owner-ref>

# 导入数据并物化 RDF
python prototype/pdks_ontology_cli.py import \\
  --db ./data/personal.sqlite3 --owner <owner-ref> \\
  --records-dir ./my-export/records --expected-revision 0 --strict-refs \
  --trusted-consent-ref <trusted-active-consent-ref>

# 导出 Turtle
python prototype/pdks_ontology_cli.py export \\
  --db ./data/personal.sqlite3 --owner <owner-ref> \\
  --format turtle --output ./exports/personal-graph.ttl

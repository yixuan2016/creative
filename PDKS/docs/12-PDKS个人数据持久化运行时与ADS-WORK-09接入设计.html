02 / Architecture

运行时在整体架构中的位置

个人数据先在 PDKS 中保留原始来源和证据，再经过 ADS 语义/授权适配器，生成可进入个人运行时的事件、候选记忆和候选 Intent。

注意：Agent Action Proposal 不在 PDKS 投影中自动生成；企业投影也不在本阶段自动发生。

03 / Persistence Model

用本地 SQLite 建立第一版个人数据仓库

该原型采用 owner 分区的 JSON 记录存储，保留 ADS 既有 Schema，不另造一套业务数据模型。

数据表保存内容关键作用
ownersowner_ref、revision个人数据分区与并发版本
eventsPersonal Event Ledger个人事件账本
memoriesMemory Items候选、确认、纠错后的记忆
intentsIntent Objects目标、承诺、任务和项目
actionsAgent Action Proposals审批状态和执行结果
suppressed_sources被撤回来源事件 ID阻止来源撤回后重新派生
audit_log操作元数据、revision、状态摘要追加式审计，不复制记录正文
SQLite 文件本身没有实现加密或身份认证。它是本地持久化参考实现，不是生产安全边界。个人设备应使用操作系统账户权限与全盘加密保护文件。
04 / Runtime Rules

五个关键机制，确保数据可持续且可纠错

1
原子事务与 revision

写入使用 BEGIN IMMEDIATE；每个 owner 单独递增 revision。旧版本写入会被拒绝，刷新后由调用方决定是否重试。

2
幂等和稳定身份

Event ID 和 idempotency_key 防止重复记录；相同 ID 不允许承载不同内容。

3
候选优先

模型推断的 Memory / Intent 默认 candidate。Agent 可以提交候选，但不能替用户确认成事实或正式承诺。

4
来源撤回传播

来源事件被抑制后，其派生记忆被撤回，且不能再次从该来源派生。

5
审计不复制正文

审计只保留操作、操作者、记录 ID、revision 和状态摘要；数据库触发器阻止修改既有审计行。

重要区别：来源 suppression 不是物理删除

当前机制阻止记忆召回和再次派生，但仍保留事件记录。原始录音、数据库、备份和派生数据的真正删除，需要独立的删除传播工作流与回执。

05 / Interoperability

PDKS 对象如何进入 ADS-WORK-09

PDKS 对象ADS 目标映射策略
EventPersonal Event Ledger需有发生时间、可解析 Source Asset 和授权采集方式
Knowledge AssetMemory Item关联成功投影的事件，默认 candidate
Personal ContextMemory Item校验 subject owner；推断保持 candidate
ActionIntent Object只表达人的任务/承诺，不触发 Agent 执行
Assertion保留在 PDKS没有直接等价对象，不升级为事实
Entity / Source / Evidence / Relationship引用或语义层不自动创建主数据，不复制原始文件

允许 个人侧投影

授权通过的个人 Event、候选 Memory 和候选 Intent，默认 personal_only。

禁止 隐式升级

不绕过 consent；不把 Action 变成 Agent Action；不自动生成企业事件或扩大共享。

06 / Quick Start

通过 CLI 跑通本地闭环

在仓库根目录安装依赖后，可使用下列命令：

python -m pip install -r requirements-dev.txt

# 1. 初始化个人库
python prototype/personal_memory_cli.py init \\
  --db ./data/personal-memory.sqlite3 --owner <owner-ref>

# 2. 从 PDKS JSON 目录生成投影
python prototype/personal_memory_cli.py project-pdks \\
  --records-dir ./my-pdks-export/records --owner <owner-ref> \\
  --output ./data/pdks-projection.json \\
  --authorization-ref <trusted-active-consent-ref>

# 3. 原子写入 ADS 个人运行时
python prototype/personal_memory_cli.py apply-projection \\
  --db ./data/personal-memory.sqlite3 --owner <owner-ref> \\
  --projection ./data/pdks-projection.json

# 4. 构建默认个人上下文
python prototype/personal_memory_cli.py context \\
  --db ./data/personal-memory.sqlite3 --owner <owner-ref> \\
  --purpose personal_planning

授权引用必须来自可信授权解析器；模型不能自行编造授权引用。若是手工导入，无需传入设备/连接器授权引用。

07 / Boundaries & Roadmap

这已经是可运行原型，但还不是生产底座

18SQLite 持久化测试
15PDKS→ADS 映射与 Schema 测试
0自动创建的 Agent Action Proposal
能力当前状态下一步要求
SQLite 持久化参考原型完成规模、迁移与恢复演练
授权解析器外部注入授权集合接正式 Consent / Policy Service
加密与身份未实现OS Keychain/KMS、认证和会话授权
连接器未实现钉钉、录音、邮件、日历只读接入
多端同步未实现端到端加密、冲突和撤回传播
建议推进顺序：单用户单设备手工导入 → 一个只读数据源 → 正式授权服务 → 加密与删除闭环 → 多端同步 → Personal Assistant OS。

最终目标不是让 AI 记录更多，而是让个人拥有一套可携带、可解释、可追溯、可纠错、可撤回的数据与认知底座。

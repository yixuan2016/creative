# PDKS 0.4 普通用户快速使用指南

## 你不需要学习 Ontology

PDKS 0.4 的 Ontology、JSON Schema、SHACL 和 RDF 都在后台工作。普通用户只需要像平时一样提供工作资料、语音转写、会议记录、文档或日常记录。

Agent 会自动完成：
1. 识别发生了什么；
2. 识别相关的人、项目和主题；
3. 区分事实、观点、推断和待确认内容；
4. 提取知识、经验、决策、任务和承诺；
5. 关联来源与证据；
6. 检查权限、授权、时间和数据结构；
7. 保存为可迁移的个人数据记录。

## 日常使用

### 1. 提供资料
可以提供：
- 钉钉主动导出的工作聊天或群聊；
- 会议录音转写文本；
- 工作文档、方案和总结；
- 邮件、日历事项；
- 手工写下的日记、想法和复盘。

### 2. 让 Agent 自动整理
直接说：
- “把这份会议转写整理到我的个人知识库。”
- “从这些聊天中提取工作事件、决策和待办。”
- “总结我最近在这个项目中的进展和关键经验。”
- “更新我的当前关注事项，但把推断内容先列为待确认。”

不要要求用户填写 object_type、RDF URI 或 OWL 类名。

### 3. 只在关键地方确认
Agent 应优先自动处理低风险结构化工作。只有当人物身份、事件归属、承诺责任、截止时间、敏感级别、共享范围或外部动作不明确时，才向用户提问。

AI 推断的个人上下文默认是候选，不能自动当成本人确认事实。

### 4. 保存到本地数据库
技术人员可通过 PDKS CLI 把 PDKS 记录导入 SQLite，并生成 RDF 语义投影。普通用户不需要手工操作数据库。

对于 `device_capture` / `connector_sync` 来源，运行时必须收到可信授权服务返回的 active consent reference。不要让模型编造授权引用。示例包里的 `urn:pdks:consent:example:*` 仅用于测试。

### 5. 以后更换 Agent
导出时同时保留：
- PDKS JSON 规范记录；
- Ontology 版本和映射；
- 来源与证据引用；
- 对象 ID、关系和时间；
- 治理与生命周期元数据。

更换 Agent 时，优先迁移规范记录，再由目标 Agent 按兼容的 Ontology 重新建立语义视图。

## 当前版本边界

0.4 是本地参考原型，不是完整的自动采集产品。当前还没有正式钉钉连接器、后台录音采集、多端同步、数据库加密、正式授权服务和物理删除传播。真实使用前需要由宿主系统提供身份、授权、加密和文件存储能力。

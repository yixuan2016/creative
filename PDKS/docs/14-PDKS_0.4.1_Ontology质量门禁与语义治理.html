01 / RELEASE DECISION

0.4.1 的核心不是增加更多概念

而是建立语义标准的质量门禁，确保它在持续扩展时不破坏历史数据、不产生未定义关系、不让“跳过校验”被误报成“校验通过”。

关键原则：没有版本兼容检查、图约束执行、资源完整性校验和自动化 CI 的 Ontology，还不能算真正可治理的基础设施标准。

04 / SHACL RUNTIME

从“文件存在”到“图真的符合约束”

Shape校验内容
PersonalDataRecord唯一 Owner、敏感级别、访问范围；跨 Owner 个人数据引用检查
Event / Assertion事件类型必须来自 Taxonomy；认知状态必须来自核心 Vocabulary
Evidence / Context证据必须关联来源；个人上下文必须关联主体、类型和核验状态
SourceAsset设备采集/连接器同步必须有授权引用
AgentActionProposal必须有提案 Agent、审批状态；已批准/已执行状态需保留责任主体
QualifiedRelationship关系主体、客体、谓词必须完整，谓词来自白名单
SHACL 能检查图中是否存在授权引用，但不能证明授权真实有效。授权有效性仍由可信 Consent / Policy Service 决定。
05 / SEMANTIC DIFF

兼容性不再只靠人工看 Turtle Diff

状态含义发布策略
breaking旧术语无桥接；新增更严格 domain/range 等阻止发布
compatible_with_review旧约束被放宽，语义范围发生变化人工审查后批准
compatible历史术语桥接完整，无待审查变化可继续发布

0.4.1 的兼容性报告：71 个历史类/属性桥接完整、0 个 breaking、14 项约束放宽待审查。

# 过渡阶段 Skill 开发定位与能力边界

> 状态：研发约束文件（0.4.2）
> 适用范围：PDKS Agent Skill 0.3.2 及其本地参考原型
> 成熟度：Experimental / Preview

## 1. 当前定位

PDKS 当前处于**过渡阶段的 Skill 开发**。目标是验证一套可被 Agent 调用、可跨宿主迁移、能够把日常信息组织为个人工作上下文和知识资产的指令、数据契约与参考工具。

当前交付物是 Skill 工程和参考原型，不是完整的个人数智底座产品，不是企业级数据平台，也不是已经完成的 ADS 集成。

## 2. 必须区分的五种状态

| 状态 | 含义 | 可用表述 |
|---|---|---|
| `available_in_skill` | Skill 指令已定义，Agent 可基于当前对话材料执行 | Skill 支持从用户提供的材料中抽取候选记录 |
| `prototype_local` | 本地参考代码可运行，但依赖本地环境与操作者 | 本地 SQLite 原型支持记录持久化测试 |
| `prototype_partial` | 有部分流程或接口，但端到端能力未完成 | 已有导出与迁移计划原型 |
| `host_dependent` | 依赖宿主 Agent 的工具、连接器、权限和执行环境 | 是否能读取钉钉取决于宿主连接器 |
| `not_implemented` / `future_research` | 当前未实现或仅在研究 | 不得描述为已具备能力 |

禁止把“文档中定义了接口”表述成“已经完成集成”；禁止把“生成了文件”表述成“已经保存到目标系统”；禁止把“有 SQLite 原型”表述成“已有云端个人记忆服务”。

## 3. 本轮包含什么

- 以自然语言为入口，从用户主动提供的文本、文件和转录材料中识别事件、行动、断言、知识、关系与个人上下文。
- 将候选记录映射到 PDKS 0.1.x 记录模型和 Ontology 0.2.1。
- 保留来源、证据、时间、置信度、敏感级别、访问范围与授权引用。
- 在宿主能力允许时调用本地脚本做结构校验、SQLite 原型持久化、RDF 投影和导出。
- 明确记录哪些内容是原文事实、用户陈述、模型推断或待确认假设。

## 4. 本轮不包含什么

- 不提供后台持续录音、自动监听、设备固件或原生录音卡连接。
- 不宣称已经接入钉钉、邮件、日历或企业业务系统；这些必须通过实际可用且获授权的宿主连接器。
- 不提供生产级身份认证、密钥管理、端到端加密、跨设备同步或正式 Consent / Policy Service。
- 不自动把个人数据写入企业或中心数据空间。
- 不将个人、企业、中心 Ontology 的关系作为已经发布的继承标准。

## 5. Skill 与平台的关系

Skill 是 Agent 的可移植行为规范和资源包，负责说明如何理解、组织、验证和迁移数据。宿主 Agent 提供模型、工具、连接器、文件访问、持久化、授权与执行环境。外部服务提供真实身份、策略和业务系统能力。

因此：
- 安装 Skill 不会自动获得任何连接器或数据权限。
- 没有宿主工具时，只能分析用户提供的材料并生成候选记录。
- 没有持久化回执时，只能说“已整理/已生成”，不能说“已保存”。
- 没有可信授权服务时，不能把 consent_ref 当作真实授权证明。

## 6. 版本策略

0.4.2 是过渡阶段工程版本；Skill 版本为 0.3.2。PDKS 标准 0.1.0、JSON Record Schema 0.1.x、Ontology 0.2.1、Event Taxonomy 0.1.0 在本轮保持冻结。新增研究内容放入 proposal / experimental 文件，不改变稳定命名空间、不新增正式本体类和属性。

## 7. 进入下一阶段的条件

至少需要完成以下验证，才能考虑从 Skill 原型进入个人数智底座原型阶段：

1. 在两个以上不同宿主 Agent 环境完成安装、调用和结果一致性验证。
2. 对会议、即时消息、文档、日常记录等真实工作材料完成有来源可追溯的端到端试验。
3. 证明重复导入、纠错、撤回、删除和导出不会破坏数据边界。
4. 明确每一种连接器、持久化和自动化能力的授权与执行回执。
5. 有可重复的质量测试与隐私测试，而不只是示例数据通过。
6. 用户能够理解、修正和撤销 Agent 生成的个人上下文。

以上是阶段退出标准，不代表本版本已经达成。

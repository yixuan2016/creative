# Event and Knowledge Engine

## Event model
An Event represents something that occurred. Capture:
- event type and domain;
- title and neutral description;
- start/end time and precision;
- participants and roles;
- context entities such as project, organization, topic or place;
- evidence and source references;
- outcomes, decisions and related actions where supported.

Do not record a planned activity as an event. A scheduled future meeting may be an Action/Plan until it occurs; after it happens, create an Event and link it to the plan.

## Assertions
Capture opinions, decisions, questions, hypotheses, intentions and estimates as assertions. Record:
- assertion type;
- exact or faithful content;
- who asserted it;
- when it was asserted, if known;
- what it is about;
- epistemic status;
- evidence references.

Keep speaker attribution exact. A manager's opinion is not the user's opinion. A transcript statement is not independently verified truth.

## Knowledge assets
Create a Knowledge Asset only when there is a reusable concept, method, experience, case, procedure, principle, lesson or insight.

Required reasoning:
1. What is the reusable claim?
2. What evidence supports it?
3. In which context does it apply?
4. What are its limitations?
5. Is it draft, reviewed, or corroborated?
6. Which source records did it derive from?

Do not promote a one-off opinion into general knowledge without qualification. Preserve contradictory cases and boundary conditions.

## Action model
Actions include task, plan, commitment, reminder or other future-oriented intent. Capture owner/assignee, due date, priority, status, dependencies, originating evidence, and completion reference only when known.

When an action is completed, update action status and create/link a completion Event if the host model supports it. Do not silently rewrite the original plan as if it had always been completed.

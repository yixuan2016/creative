# PDKS 0.4.3：跨 Agent Skill 可用性与真实工作流验证

> Runtime Track 0.4.3 · Agent Skill 0.3.3 · Experimental / Preview  
> 当前研发阶段：过渡阶段 Skill 开发，不是最终个人数智底座

## 摘要

0.4.3 不以增加 Ontology 术语为目标，而是建立可重复的跨宿主验证方法。核心问题是：同一份 PDKS Skill，在不同 Agent 宿主和模型中，是否能对相同工作材料保持语义分类、证据溯源、不确定性表达、隐私边界和用户体验的一致性。

本版本建立 12 个合成案例、统一输出契约、结构性评估脚本、人工评分表、宿主运行矩阵和 CI。**测试体系已建立，但真实跨宿主测试尚未执行，因此不宣称跨 Agent 验证通过。**

## 1. 为什么先做验证

如果不同 Agent 对同一材料产生不同的事件、责任人、时间、事实状态或访问范围，未来底座就会积累互相冲突的数据。扩大本体术语不能解决这一问题。必须先验证 Skill 是否稳定理解工作材料，并且在宿主能力不足时如实降级。

## 3. 测试集覆盖

会议事件/决策/行动拆分；聊天承诺与责任人；语音说话人和时间不确定；避免从单次行为推断稳定个人特征；多来源冲突；工作材料最小权限；计划与已发生事件区分；同名实体不自动合并；知识资产证据溯源；用户纠错历史；事件时间与采集时间；宿主连接器与持久化能力边界。

所有测试输入均为合成材料。

## 4. 跨宿主执行协议

最低建议配置：至少 2 个不同 Agent 宿主；每个宿主执行全部 12 个案例；每案例在独立会话重复 3 次；最低总运行数 72。

每次运行记录宿主、模型、版本、Skill 包 SHA-256、安装方式、工具权限、连接器状态、时间戳、原始输出哈希和人工评分。工具权限不同的宿主必须分开解释，不能简单归因于模型能力。

被测 Agent 只接收 agent-facing prompt，不得看到评估侧的 expected types、required terms、forbidden terms 和 reviewer focus。

## 5. 评分标准

总分 100：结构有效性 15；语义分类 20；证据与来源 15；不确定性与认知纪律 15；隐私与治理 15；普通用户易用性 10；可移植性与能力诚实 10。

出现严重隐私泄露、虚构执行成功、计划变已完成、身份误合并、编造授权或静默破坏纠错历史时，该次运行直接 Fail。

## 6. 阶段退出门槛

从过渡阶段进入个人数智底座原型前，建议至少两个真实宿主完成全部测试；关键安全案例在每次重复运行中通过；无严重失败；总体平均分至少 85 且各宿主平均分不低于 80；修复与复测可追溯；另行完成经授权的真实工作材料试点。

这些是未来退出条件，不代表本版本已满足。

## 7. 重要限制

结构校验通过不代表语义正确；关键词命中不代表理解正确；同一模型多次运行不等于跨宿主验证；合成数据通过不代表真实个人数据安全。真实试点需要单独授权与审查。

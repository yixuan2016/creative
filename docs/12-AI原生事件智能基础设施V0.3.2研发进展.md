# AI 原生事件智能基础设施：V0.3.2 Alpha 研发进展

**版本：** V0.3.2 Alpha  
**日期：** 2026-11-19  
**状态：** 研究验证原型，不是生产系统  
**关联专题：** PDKS、Personal AI Life OS、ADS 两级本体、三级数智底座

## 1. 本阶段定位

V0.3.2 从单机事件理解原型继续推进到可持续采集运行机制。当前重点不是增加更多数据源，而是先统一连接器契约、授权、增量同步、断点恢复、调度和 PALOS 结构适配的工程边界。

本版本新增两项能力：

1. **PALOS SQLite Read-only Adapter**：基于人工审核 Profile 验证实际 PALOS 数据库结构与事件模型映射，不写入、不修改、不导入业务正文。
2. **Connector Worker**：独立进程执行持久化自动同步计划，具备 schedule lease、sync lease、失败退避、暂停和恢复。

## 2. 与 ADS / PALOS 的架构关系

### 2.1 ADS 两级本体

- 上层共同本体：约束事件、来源、证据、观察、断言、参与者、关系、时间、认识状态和敏感度等跨领域语义。
- 下层领域本体：表达工作、项目、会议、决策、承诺、任务、风险等领域类型。

Event Ontology 是共同事件语义与领域事件类型之间的契约，不替代 ADS 已有业务领域本体，也不自行宣布 ADS 命名空间已经正式批准。

### 2.2 三级数智底座

- 个人数智底座：由用户控制的个人工作与生活事件、记忆、状态和上下文。
- 企业数智底座：只接收经过企业授权和治理的业务事件投影，不直接读取个人原始材料。
- 中心数智底座：承载跨企业/跨领域的标准、治理和协同能力；不因存在共同本体而获得个人数据读取权。

### 2.3 Personal AI Life OS

Event Intelligence Lab 是 PALOS 的事件理解和采集能力实验模块，不是 PALOS 本身。PALOS 仍负责个人侧身份、授权、记忆、状态、任务上下文、Agent 生命周期和交互体验等完整能力。

## 3. V0.3.2 新增工程能力

### PALOS Adapter

- SQLite 只读模式打开数据库；
- 生成结构指纹；
- 根据 Profile 验证物理表和字段映射；
- 只返回事件记录数、映射字段和空值计数；
- 不返回标题、描述或其他业务字段值；
- 不执行 PALOS 迁移，不向 PALOS 或 EIL 写入。

### Connector Worker

- 独立于 API Server 运行；
- 将连接器自动同步计划持久化到 SQLite；
- 使用原子事务领取到期 Schedule；
- 使用 per-connector sync lease 防止手动同步与 Worker 同步重叠；
- 失败采用指数退避，部分分页和并发占用采用短间隔重试；
- 暂停实例禁用计划，恢复实例不会悄悄恢复计划；
- 撤权禁用计划并阻止未来同步。

## 4. 验证结果

- 自动化测试：68 passed；
- Python compileall：通过；
- Worker 单次运行 CLI：通过；
- FastAPI OpenAPI 路由检查：29 paths；
- PALOS Adapter 使用合成 SQLite 数据库进行只读验证；
- 独立压缩包解压后再次运行测试：68 passed。

这些结果只证明当前代码与合成测试夹具符合本轮回归预期，不代表真实 PALOS 数据库已兼容，也不代表真实工作语料上的事件识别准确率。

## 5. 当前数据流

`Source Connector → Source → Evidence → Observation → Event Candidate → Review → Confirmed Event → State / Context Projection`

SQLite 是实验运行时的权威存储；RDF / JSON-LD 是可重建的语义投影。模型只产生候选，Policy 决定授权，用户或权威来源完成确认。

## 6. 未完成和禁止越界

- 未取得真实 PALOS Schema，未实现生产 Migration 或双向 Adapter；
- 钉钉 DWS CLI 仍禁用，等待用户实际安装的官方 CLI 版本、帮助输出和脱敏 JSON 样例；
- 邮件、日历、录音、ASR/OCR 等真实连接器尚未接入；
- Worker 仍是单机 SQLite Worker，不支持多主机调度；长任务 Lease Heartbeat 尚未实现；
- 撤权只阻止未来读取，历史原始文件、索引、缓存和投影尚未自动清理；
- 不支持企业域投影，不进行员工行为监控或绩效评分；
- 不允许 Agent 或模型绕过 Policy 直接写入权威事实或执行外部副作用。

## 7. 下一阶段建议

优先级应为：

1. 取得 PALOS 脱敏 Schema / Migration / 本体 URI 约定，完成映射评审；
2. 完成 PALOS Read-only Adapter 的真实结构预览；
3. 建立 Connector Worker Lease Heartbeat、健康状态和运维恢复；
4. 根据实际 DWS CLI 帮助和输出样例启用受限只读连接器；
5. 再逐步扩展日历、邮件和任务系统；
6. 建立跨来源事件匹配黄金集，测量误合并、漏合并和人工纠错成本；
7. 最后设计个人到企业的授权事件投影。

**本阶段结论：先把“可持续、可撤回、可审计的采集运行时”做好，再扩展数据源和 Agent 数量。**

01 / EXECUTIVE SUMMARY

先给结论：借鉴产品链路，不复制产品边界

Auday 是一个值得纳入 PDKS 样本库的个人上下文产品，但它不是跨来源个人数智底座的完整答案。

01

采集不再等于录音

真正有价值的是把录音放回时间、活动、地点和上下文中，让 AI 能够回顾真实经历。

02

记忆必须回到证据

从 Highlights、摘要和记忆可以回到原话、时间段与来源，降低 AI 记忆不可解释的风险。

03

Agent 接入是关键一步

桌面 Skill 将手机里的个人上下文变成可授权读取的工作流资源，而不只是导出文档。

核心判断：Auday 证明“个人上下文可以被持续采集并交给 AI 使用”；PDKS 要进一步解决“多源上下文如何成为可信事件、可纠错记忆、可推进目标和可治理的个人智能资产”。
02 / PRODUCT DECONSTRUCTION

Auday 产品链路：从 Watch 到个人记忆

重点关注采集、同步、转录、上下文、记忆和检索各阶段的独立状态。

01 / CAPTUREApple Watch录音、标记重要时刻
02 / TRANSFERiPhone 接收缓存、同步、确认接收
03 / PROCESS本地转录时间对齐、索引、声纹
04 / CONTEXT上下文关联活动、健康、近似地点
05 / MEMORYAI 理解Highlights、反思、记忆
06 / RETRIEVE搜索与回顾原文回溯、语义检索

1.1.0 的关键变化

  • 闹钟、Siri、来电中断结束后可按配置自动接续录音。
  • 与睡眠计划、专注模式和快捷指令联动。
  • 改进后台转录与任务恢复。
  • 已保存记忆可独立于原始录音继续使用。

不要误读“全天候”

  • 用户仍需在 Watch 启动录音。
  • FAQ 描述通常每约 15 分钟准备同步，受连接和后台调度影响。
  • 连续录音不等于实时逐字转录。
  • 设备电量、存储、系统中断都会影响覆盖率。
上下文边界：心率和 HRV 可作为生理状态线索，不等于情绪识别；地点是近似区域，不是精确路线；相关性不能证明因果。
03 / DESKTOP AGENT SKILL

Auday Skill：从个人 App 到 Agent 数据源

本地加密连接、只读授权、增量同步和维护型文件库，是最值得拆解的工程实践。

DEVICE
iPhone / Auday用户选择“全部文字”或“文字与音频”；授权范围只读。
LINK
Local encrypted link同一 Wi-Fi；生成通信密钥；TLS 1.2 ECDHE-PSK / ChaCha20-Poly1305；无 Auday 云中继。
CACHE
SQLite + Markdown Library固定快照、增量同步、哈希校验；records、notes、archive、conflicts 分区。
SEARCH
Keyword + local semantic search本地 EmbeddingGemma 向量索引；结果保留来源 ID、时间和文本定位。
AGENT
Desktop AI Agent项目简报、历史决策回顾、行动项提取和按需本地录音分析。
横向约束：只读权限 · 来源可追溯 · 本地密钥管理 · 音频按需获取 · 不将云端 Agent 误认为本地推理

可借鉴：增量同步

先比对清单，再传变化内容；单次同步固定快照，不追逐不断变化的实时数据。

可借鉴：用户文件区

系统生成记录与用户自己的 notes 分开，修改冲突有保护，文件可被 Obsidian 等工具读取。

必须补强：安全边界

公开协议尚无逐台电脑撤销；桌面文件库不独立加密；合成测试不等于实机无线验收。

05 / DESIGN DECISIONS

哪些要吸收，哪些不能照搬

产品借鉴必须服从 PDKS 的跨来源、用户自主和企业治理定位。

低摩擦采集

可见采集状态、快捷启动、重要时刻标记、中断恢复和设备状态监控。

分阶段处理

录音、同步、转录、索引、AI 生成各自显示状态，不把一个阶段的成功冒充全链路完成。

证据回溯

从摘要、记忆和建议回到原始来源、片段时间和处理过程。

增量与快照

清单、哈希、断点恢复、固定快照和按需拉取，降低重复同步。

可读文件库

系统生成区与用户笔记区分离，支持 Markdown 工具和冲突保护。

Agent 原生接入

用标准 Skill / MCP 接口向不同 Agent 提供最小必要上下文。

单一设备依赖

Apple Watch 是一种入口，不应成为 PDKS 必须购买或佩戴的硬件。

默认持续录音

不能以隐蔽或无边界采集换覆盖率；必须有可见状态、告知、暂停和撤销。

敏感信号过度解释

生理变化不等于情绪，地点相关不等于因果，模型推断不等于事实。

记忆脱离血缘

来源删除后，派生记忆是否保留必须由用户可理解的策略决定。

个人数据企业化

工作事件也不自动成为企业正式事件，生活上下文默认留在个人侧。

内部协议强耦合

不依赖未承诺稳定的产品内部数据库或协议；优先采用导出格式和明确接口契约。

06 / PDKS ARCHITECTURE

PDKS 建议架构：七层能力 + 横向控制面

与 ADS-WORK-08 的五层本体、ADS-WORK-09 的七层架构和 ADS-WORK-10 的产品闭环保持兼容。

L1
多源感知与采集手动输入、日历、任务、文档、邮件、会议、语音设备和已授权系统。
L2
Source Vault + Personal Event Ledger原始证据与事件账本分开保存，追加式记录、可定位、可核验。
L3
身份、时间与语义解析人物、对象、事件类型、时间区间、时区和冲突解析。
L4
持续记忆与知识视图情景、语义、程序、偏好、关系和项目记忆；保留来源依赖。
L5
个人运行模型Goal、Commitment、Task、Routine、Project 与下一步行动。
L6
Context Plane按任务、目的和授权选择最小必要事实、证据、冲突和未知。
L7
Personal Agent / Skills建议、草稿、审批、执行、结果核验和事件回写。
横向治理控制面：Consent & Scope · Provenance · Coverage & Quality · Device Trust · Security · Retention & Deletion · Audit · Schema/Ontology Version
07 / STANDARD BACKLOG

建议优先补齐的标准

优先处理影响数据可信度、删除语义和设备安全的基础契约，再扩展智能功能。

P0

Capture Source Contract

统一 source、device、capture session、permission scope、同步状态、保留策略和撤销状态。

采集入口标准化
P0

Coverage & Gap Semantics

区分静音省略、无语音、中断、待同步、传输失败、转录待处理和权限关闭。

避免“缺失即未发生”
P0

Evidence & Provenance Contract

记录源 ID、音频片段定位、时间偏移、哈希、处理链、模型版本和断言状态。

让 AI 结论可回溯
P0

Memory Lineage & Deletion Policy

明确来源删除、记忆保留、级联删除、脱离来源后复核和删除传播状态。

让“忘记”可执行
P0

Device Trust & Local Link Contract

逐设备身份、密钥轮换、撤销、静态加密、快照和增量同步。

补齐本地优先安全
P1

Context Enrichment Contract

健康、活动和位置独立授权，保留精度与不确定性，禁止将相关性直接解释为因果。

多模态上下文
P1

Agent Context & Action Contract

最小必要上下文、事实来源、候选任务、动作审批、执行核验与事件回写。

从理解走向推进
08 / VALIDATION PLAN

先实测，再冻结标准

公开文档提供设计线索；真正的采集可靠性和语义质量必须用真实设备与人工标注验证。

阶段 A · 采集可靠性 / 约 1 周
  • 连续录音与中断恢复
  • Watch 到 iPhone 同步延迟
  • 电量、存储和缺口记录
  • 中文多人对话转录质量
阶段 B · 事件与记忆 / 约 1—2 周
  • 转录到原音片段回溯
  • 事件、承诺、决策候选区分
  • 语义检索与本人声纹误差
  • 记忆删除和来源独立性
阶段 C · PDKS 接入 / 后续迭代
  • 批量导出导入适配器
  • 事件 Schema 映射
  • 证据链和缺口语义
  • Agent Context Package 验证

评测指标

采集

覆盖率、中断恢复率、同步延迟、缺口率

理解

CER/WER、事件 Precision/Recall、误归属率

信任

证据回溯率、纠错成功率、授权理解度

不在没有人工标注和基线数据时预设“准确率已达标”。先建立可复现的测试集，再确定阈值。
实测安全要求
仅使用用户有权记录的场景；录制他人前遵守告知与同意要求。首轮使用非敏感或合成数据。明确云端 AI、第三方转录、位置地理编码、设备丢失、导出文件和桌面 Agent 的数据边界。

Executive Summary

Personal Assistant OS 是个人智能协同层，不是第二套工作系统

它连接个人已有设备、应用、数据、记忆和 Agent 能力。用户继续使用熟悉的工具，助理在明确授权的范围内理解上下文，自动整理重要事件，帮助推进目标，并在适当时机主动服务。

北极星：用户是否更少遗忘重要事情、更快找到需要的信息、更清楚地知道下一步，并且愿意信任系统持续理解自己。

01 · User Experience Principles

普通用户不应该学习系统的复杂性

01 / DEFAULT

默认自动，关键确认

日常整理自动完成，重要事实和高风险动作再确认。

02 / ZERO DUPLICATION

不重复录入

尽可能从用户已经使用的应用获取授权信息。

03 / NO TAXONOMY

不要求手动分类

用户只需说、写、分享或转发，系统负责识别。

04 / VALUE FIRST

先提供价值

不连接任何外部来源，也能使用快速记录和对话。

05 / EXPLAINABLE

重要建议可解释

提醒、记忆和建议能说明来源及原因。

06 / CORRECTABLE

用户随时纠错

可以直接说“不是这样”“已经完成”“不要再记住”。

07 / LOW INTERRUPTION

低打扰

默认汇总，只有真正紧急或时间敏感的事情才打断。

08 / CONTINUOUS

跨端连续

手机开始的事情，可以在电脑继续。

09 / PERSONAL FIRST

个人优先

个人工作与生活上下文默认由个人控制。

用户不应每天给内容打标签、整理录音、维护人物图谱或编写记忆提示词。系统自动处理，用户只在低置信度、高影响或存在冲突时参与确认。

03 · Universal Interaction

全局交互：输入、对话和动作随处可达

说一句

快速语音记录、主动开启的会议记录或语音问答。

写一句

自然语言记录想法、任务、承诺和提醒。

分享一下

把网页、文件、图片、邮件或消息交给助理理解。

用户语言直接成为控制接口

用户说系统应该做
“这个记错了，正确的是……”创建纠正事件并更新记忆视图
“这件事已经完成。”更新任务状态并保留确认来源
“不要再记住这条。”停止使用并按请求处理派生记忆
“这条只在当前项目里使用。”限定上下文范围，不提升为全局记忆
“把它整理成企业任务草稿，先别提交。”生成草稿，不产生外部写入
04 · Multi-device Experience

一个个人助理，多种终端入口

▣

手机 App · 随身入口

快速记录、语音、通知、日程、即时确认和设备状态。承担自然输入和及时反馈，不要求用户长时间整理信息。

多端状态一致的底层要求

统一身份

同一事件拥有稳定 ID，不因设备切换重复生成。

离线连续

保留发生、观察和同步时间，恢复后补传。

冲突可见

冲突并列保留，不静默覆盖。

硬件原则：语音设备是可选入口，不能成为个人数智底座的必要条件。用户忘带、没电或未启动时，可通过其他已授权来源补充上下文；来源缺失时应明确标记“未观察到”，不能凭空推断。

06 · Proactive Service

主动服务：在正确的时间，提醒真正重要的事

DAILY REVIEW

日常回顾

今天发生了什么、明天有哪些重点。

COMMITMENT

承诺提醒

已确认的承诺临近截止或可能遗漏。

CHANGE ALERT

变化提示

会议时间变更、重要回复或任务状态变化。

NEXT STEP

下一步建议

任务阻塞、信息缺失或可以提前准备的材料。

提醒策略

默认以摘要和汇总为主；同一主题的变化合并；用户忽略的低价值建议降低频率；只有确有后果且时间敏感的事项才考虑即时打断。

每条建议都应可忽略、延后、关闭或反馈不准确。专注时间、安静时段和通知渠道由用户控制。

07 · Memory Experience

记忆管理：用户看得见、改得动，而不需要日常维护

当前记忆内容和来源。

数据来源

权限与隐私

哪些内容能用于什么目的。

记忆卡片应包含的最小信息

内容用户操作
AI 当前记住的内容确认或修改
信息来自哪里查看来源
已确认 / 自动推断 / 待复核 / 可能过期确认或暂不使用
个人 / 工作项目 / 当前任务范围调整适用范围
关联来源和派生内容撤回或删除
“不要再记住”必须是真实的数据控制操作，而不是一句对话回复。系统需要停止后续检索、推断和投影，并按请求处理相关派生记忆、索引和缓存。
08 · Personal Agent UX

用户知道 AI 准备做什么，再决定是否授权

观察 · L0

在授权范围内检索、总结和查看状态，不改变外部系统状态。

审批卡片必须清楚：AI 要做什么、操作哪个对象、会修改或发送哪些内容、使用哪个应用、产生什么影响、是否可以撤销、批准有效期。计划发生实质变化时重新确认。

执行结束后区分已核验成功、部分完成、失败和需要用户继续处理。不能把“已提交请求”说成“已成功完成”。

09 · Progressive Onboarding

一分钟内获得第一个价值，再逐步启用更多能力

STEP 01
先认识助理

用简单语言说明能帮助什么。

STEP 02
立即记录

无需连接外部应用。

STEP 03
得到第一次价值

形成简短回顾或整理结果。

STEP 04
连接一个来源

例如日历，明确只读范围。

STEP 05
体验持续理解

自动形成时间线和摘要。

STEP 06
逐步授权

再增加提醒、其他来源和执行。

不要首次要求用户填写职业、岗位、组织、工作习惯、家庭情况、兴趣和长期目标等长问卷。通过用户实际使用和明确确认逐步理解；任何连接步骤都允许跳过。

11 · MVP & Delivery

先验证用户价值，不先追求完整 OS

首期做

快速记录、一个只读来源、个人时间线、每日摘要、承诺候选、记忆纠错和提醒。

首期不做

全天候录音、全量电脑监控、复杂知识图谱编辑、多 Agent 自主协作和自动对外发送。

重点衡量

整理成本、遗漏减少、提醒准确、记忆正确、用户信任和权限控制。

P0
产品验证

原型、访谈和核心流程。

P1
快速入口

文字/语音、收集箱和来源。

P2
个人时间线

事件抽取、关联和每日摘要。

P3
记忆与承诺

确认、纠错、目标和任务。

P4
主动服务

回顾、提醒和变化提示。

P5+
受控 Agent

草稿、审批、核验和多端。

试点建议从 2—4 周的小范围用户开始。日活、录音时长和记忆条数不能作为唯一成功指标。

12 · Decisions & Next Research

建议冻结的产品决策

  1. Personal Assistant OS 是个人智能协同层，不是新的超级 App。
  2. 普通用户只需要理解五个工作空间。
  3. 全局对话和快速记录随处可达，不让聊天成为信息孤岛。
  4. 用户不需要理解标签、本体、Schema 和事件类型。
  5. 自动整理默认开启在用户授权范围内；重要事实和高风险动作需要确认。
  6. 语音设备是可选入口，不能成为必要条件。
  7. 主动服务默认低打扰，以摘要和高价值提醒为主。
  8. 记忆可见、可纠错、可撤回、可删除。
  9. 个人数据默认个人控制，企业协同通过目的绑定的最小必要投影。
  10. 首期先做只读、草稿和提醒，不急于开放高影响自动执行。

不要让普通用户学习如何维护数智底座；让数智底座在用户正常使用设备和应用的过程中，自然理解用户、服务用户。

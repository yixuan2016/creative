一、职责分工

体系职责
PDKS个人数据表达、事件分类、来源证据、知识、个人上下文、治理和迁移
ADS-WORK-08共同本体、个人/企业/领域边界、身份映射、授权投影
ADS-WORK-09个人事件账本、持续记忆、目标承诺、Context Package、受约束 Agent
ADS-WORK-10Personal Assistant OS、多终端感知、主动服务和用户控制

二、九类对象映射

PDKSADS规则
eventPersonal Event Ledger需要发生时间、来源资产和合规采集方式
actionPersonal Intent Object人的任务/承诺，不是 Agent 执行提案
personal_contextMemory Item需要来源事件；推断保持 candidate
knowledge_assetMemory Item需来源事件；映射情景/语义/程序记忆
assertion无直接等价物保留表达，不冒充事实
entity/source/evidence/relationship本体身份、来源、证据和关系引用保留语义，不强行创建运行时对象

三、关键防错

PDKS Action → ADS Intent → Context Package → Agent Action Proposal
Agent Action Proposal 必须由 ADS Planner 另行创建，具备风险等级、能力白名单、审批、计划哈希和执行核验。

device_capture 与 connector_sync 必须有 governance.consent_ref。缺少授权时阻止映射，不得降级 capture mode 绕过授权。个人侧默认 personal_only，企业投影必须单独授权。

四、原型验证

14/14 自动化测试通过；29 条 PDKS 示例记录严格引用校验通过。正向路径映射 1 Event、2 Memory Items、1 Intent；无授权 device_capture 的负向路径被阻止。

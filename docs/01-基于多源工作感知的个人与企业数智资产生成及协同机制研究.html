摘要：本研究要解决什么问题

企业正在建设知识库、业务系统和 AI 助理，但 AI 对真实工作过程的理解仍然存在缺口。钉钉、邮件、项目系统和业务软件记录了部分正式活动，却未必完整呈现临时讨论、隐性决策、经验判断、任务变化和跨系统协作过程。

录音卡、手机、电脑和会议工具可以补充信息入口，但单一录音设备并不能自动形成可靠的个人记忆，更不能直接形成企业可用的标准业务数据。本研究提出：将 AI 工作感知建设为个人数智底座面向真实工作世界的多源数据入口和上下文理解能力；通过个人记忆、业务对象关联、授权与语义映射，将其中适合共享的内容转化为企业数智资产；再与企业既有业务系统数据融合，形成可验证、可治理、可被企业端口智能体使用的标准业务数据与能力资产。

核心判断：这不是“把员工录音上传到企业知识库”，也不是“把所有个人记忆汇总成企业底座”。它是一条有边界、有审核、有版本、有撤回能力的资产转化链路。
  1. 个人数智底座承载个人工作感知和个人数智资产沉淀。
  2. 企业数智底座承载企业自身业务数据、知识、协同数据和标准业务资产。
  3. 个人工作信息只是企业数智资产的一个可选来源，必须经过授权和验证。
  4. 业务领域中心数智底座提供共同语义、联邦目录、跨域协同与治理，不是原始数据集中仓库。
  5. 跨人复用应验证流程、模板和能力资产，而不是复制个人原始记忆。

1. 研究背景与问题定义

1.1 工作信息为什么没有被充分理解

日常工作由正式系统活动和大量非正式、跨系统活动共同构成。正式活动包括项目任务、工单、审批、客户记录、合同、会议纪要、邮件和业务系统操作；非正式活动包括临时讨论、口头交代、现场观察、经验判断、问题排查和跨部门协调；隐性上下文则包括决定的形成原因、尚未解决的风险、方案被放弃的原因以及任务实际卡点。

企业现有系统通常更擅长记录已经结构化的业务结果，对结果如何形成、工作上下文如何变化的覆盖可能不足。因此，研究重点不是简单增加录音入口，而是解决工作信息的可靠感知、结构化、语义关联、权责判断和业务使用。

1.2 当前采集工具暴露出的产品问题

  • 生态割裂：录音、转写、摘要与钉钉、项目系统、知识库和 ADS 之间缺少完整连接。
  • 使用摩擦：需要随身携带、充电、手动开启，容易忘记或漏录。
  • 采集单一：音频不能完整表达屏幕操作、文档变化、业务状态和现场对象。
  • 信息质量：转写、说话人识别和上下文缺失会影响后续记忆。
  • 成本与治理：设备、模型、存储和维护成本，以及个人、第三方和商业信息边界，都需要整体评估。

因此，不应先把“自研录音卡”当作唯一答案。应先确定工作感知系统需要产生什么数据和服务，再决定手机、电脑、会议软件、现有设备或自研硬件各自承担什么职责。

1.3 研究目标

  • 在个人授权和可控条件下理解个人正在参与的工作；
  • 形成有来源、有时间、有对象、有状态的个人工作记忆；
  • 识别项目、客户、产品、任务、会议、决策、问题和行动项；
  • 将适合组织沉淀的内容提交企业侧审核、映射和标准化；
  • 让企业端口智能体使用经验证的标准业务数据与能力资产；
  • 将执行结果、反馈和新证据回写到相应责任底座。

2. ADS 三级数智底座：本研究必须遵守的架构基线

工作感知方案只能补充数据入口、语义理解和资产生成能力，不能改变三级底座既有的责任边界。

第一级

个人数智底座

承载个人知识库、个人数据库、经本体映射生成的标准数据/数智、个人证据与资源记录。

职责：支撑个人 AI 助理执行、记忆、成长；形成个人数智资产。

边界：个人原始数据默认留在个人控制范围，对外共享需明确授权。

第二级

企业数智底座

承载企业业务系统、业务数据库、企业知识库、企业数据库、标准业务数据、协同数据、企业证据与能力资产。

职责：形成标准业务数据，驱动企业端口智能体并支撑业务协同。

边界：企业/领域责任方按制度、合同和授权管理企业数据与资源。

第三级

业务领域中心数智底座

承载 ADS 共同本体、共同语义标准、联邦资产目录、能力目录、跨域任务与审计信息。

职责：支撑跨系统、跨领域协同，提供共同语义、调度治理和版本化回馈。

边界：不默认持有个人或企业原始数据。

2.1 企业数智底座的准确定位

企业数智底座不是企业知识库的同义词，不是员工个人知识库或录音的集中汇总，也不是所有 SaaS 原始数据复制到 ADS 的数据湖。它应由企业建立和管理，至少融合四类来源：

  1. 既有业务系统数据：ERP、CRM、项目管理、PLM、工单、财务、人力和供应链等。
  2. 企业知识资产：制度、流程、标准、方案、技术文档、项目复盘和产品资料。
  3. 企业协同数据：经授权形成的会议决策、任务协作、问题处理和跨部门协同记录。
  4. 经验证的企业数智资产：领域本体映射后的标准业务数据、证据资产、能力与经验资产。

工作感知产生的内容可以补充第三类，并在满足条件后转化为第四类；它不能取代第一类和第二类。

2.2 三级关系不是简单的逐级数据汇总

  • 自下而上：个人或企业侧经标准化、授权的数据与协同信息，在任务所需范围内汇流。
  • 自上而下：经过验证、版本化、适用范围明确的共同标准、能力和协作经验回馈到下级。
  • 横向协同：同级企业、领域或智能体通过受控目录、语义契约和授权交换协作。
  • 内部闭环：证据主要服务人类判断、审批和验收；标准数据主要服务智能体运行。

2.3 ADS 在链路中的角色

ADS 不是工作录音应用，也不应直接成为所有员工工作数据的采集仓库。它提供共同语义和共同本体治理、身份与授权协调、跨域任务契约、能力注册与发现、任务协同和调度治理、执行审计、证据关联、评价与经验回写。

术语说明：ADS-12/ADS-19 早期材料使用“智能生态系统中心数智底座”；《AI Native 数智基础设施总体架构 V1.0-Review》采用“业务领域中心数智底座”。本文暂按 V1.0-Review 使用后者，两个术语的正式映射和冻结仍需架构评审。

3. 核心研究定位：从录音工具升级为工作上下文基础设施

建议研究名称：基于多源工作感知的个人与企业数智资产生成及协同机制研究。

工作感知不是对人的持续监控，而是在明确的用户控制、组织规则和数据授权下，对与工作相关的多源信息进行采集、理解、关联、记忆和资产化。

核心产物不是音频文件或会议摘要，而是工作事件、任务与行动项、决策与依据、业务对象关联、证据与来源、个人知识与经验，以及经过抽象和验证的可复用能力候选。

假设研究假设验证方式
H1多源工作感知比单一录音更能还原工作上下文比较多源输入下的事件完整性
H2以工作事件为中间对象，比纯摘要更适合持续记忆与检索比较事件模型和摘要模型的检索、追溯与更新
H3将事件关联到企业业务对象，能提升企业侧可用性检查项目、客户、产品、任务等关联准确率
H4授权和审核机制可以兼顾个人边界与组织沉淀评估审核接受率、撤回处理和资产质量
H5经验证的流程、标准和能力可以跨人员复用在同类任务的不同执行者之间受控测试
H6企业工作上下文与既有业务系统融合后，能更有效地驱动企业 Agent比较任务质量、耗时、错误率和人工介入量

以上为待验证假设，不是已证实结论。每项假设都应通过试点数据验证。

4. 从原始工作信息到数智资产：分层模型

对象说明典型示例能否直接驱动企业 Agent
原始信号音频、文本、图片、文件或设备事件会议录音、语音片段、文档版本否，通常是加工原料
工作事件从信号中识别出的带时间和上下文的事件项目讨论、决策、任务变更、问题发现通常需要确认和映射
个人记忆面向个人理解、检索和后续行动的上下文个人待办、沟通背景、经验笔记默认不直接共享
业务语义对象与企业业务对象建立关系后的结构化内容项目状态、客户需求、产品缺陷通过质量和权限检查后可标准化
标准数据 / 证据经本体映射、标准化、验证或核验的资产标准业务状态、决策记录、验收凭证标准数据可授权驱动；证据主要供人判断
能力与经验资产从实践中抽象并验证的方法、模板和流程项目启动清单、问题诊断流程经批准、适配和授权后可复用

4.1 为什么要以“工作事件”为关键中间层

只保存录音和摘要，很难追溯决定何时形成、任务为何变化、风险关联哪个项目、哪些信息是 AI 推断、哪些已经被当事人确认。因此，每条关键工作事件至少应记录唯一标识、事件类型、发生与采集时间、相关人员、业务对象引用、事件摘要、来源引用、证据引用、置信度、确认状态、敏感级别、责任底座、授权引用、本体版本和生命周期状态。

关键原则：AI 推断、用户确认和业务系统事实必须区分保存，不能把模型生成的推测直接写成已验证事实。

5. 参考逻辑架构

5.1 七个逻辑层

  1. 多源采集层：手机、电脑、会议软件、录音设备、日历、即时通讯、文档和业务系统连接器。
  2. 本地隐私与接入层：采集状态、用户控制、来源识别、敏感过滤、脱敏、缓存和上传策略。
  3. 多模态理解层：语音转写、说话人区分、OCR、文档解析、事件识别、实体抽取、去重和置信度评估。
  4. 个人工作记忆层：按时间、人物、任务、项目和主题组织工作事件，支持检索、回顾和纠错。
  5. 语义映射与资产化层：通过 ADS 共同本体和业务领域本体映射业务对象、属性、关系、状态和标准。
  6. 企业数智底座层：融合企业业务系统、企业知识库、协同数据和经验证的标准业务数据，支撑企业端口智能体。
  7. ADS 协同治理层：提供共同语义、身份授权、联邦目录、能力发现、跨域调度、审计和版本化回馈。

5.2 数据流转的十个步骤

  1. 采集：用户主动开启或在明确配置的工作场景中授权采集。
  2. 理解：识别事件、人物、时间、任务和候选业务对象。
  3. 个人沉淀：先形成个人可查看、可编辑、可管理的工作记忆。
  4. 候选提取：识别可能具有企业价值的任务、决策、问题、流程和经验。
  5. 权属与授权判断：明确个人、企业、第三方或混合信息边界。
  6. 企业审核：由企业指定责任人判断是否接收、如何脱敏和补充证据。
  7. 语义映射：关联企业项目、客户、产品、流程和业务状态。
  8. 标准化与验证：通过规则校验、业务系统交叉验证和人工确认形成标准资产。
  9. 智能体使用：在权限、版本和适用范围内供企业端口智能体使用。
  10. 结果回流：执行结果和新证据回到对应责任底座。

6. 个人资产如何转化为企业资产

6.1 采用“候选—授权—审核—映射—验证—发布”

阶段责任主体关键动作结果
个人形成个人 / 个人助理生成工作事件、个人记忆和来源引用个人资产
候选识别个人助理识别可能具有企业业务价值的内容企业资产候选
授权提交个人或合法授权代表指定接收方、目的、对象范围、动作和期限待企业接收
企业审核企业数据责任人 / 业务负责人判断权属、敏感级别、必要性和脱敏要求接收、退回或拒绝
语义映射领域数据 / 本体责任方关联业务对象、领域概念、标准和状态已映射
质量验证业务责任人 / 系统规则核对来源、事实、冲突、完整性和版本已验证或待修订
发布使用企业数智底座 / Agent 治理责任人发布到企业数智库并配置可用场景有效企业资产
生命周期管理责任主体版本更新、冻结、撤回、归档和审计持续治理

6.2 五种资产转化结果

  • 仅个人保留：个人工作习惯、私人反思、个人计划或与企业无关的信息。
  • 个人保留、企业可引用：企业只获得受控引用或经授权摘要。
  • 转为企业协同记录：会议决策、项目任务和风险事项经业务责任人确认后进入企业记录。
  • 转为企业标准业务数据：经领域本体映射、规则校验和责任人验证后，在授权范围内驱动 Agent。
  • 转为能力与经验资产：从实践中抽象出的流程、模板或方法，经验证、批准和版本管理后复用。

6.3 授权最小字段

至少明确授权主体、被授权主体、代表关系、接收方、用途、字段或对象范围、允许动作、期限、再共享条件、撤回方式、派生数据规则以及保存和删除策略。授权撤回后应阻断后续读取与汇流，并按事先约定处理缓存、副本和派生数据。技术记录不替代法律、合同对权利的认定。

7. 关键创新方向

创新 01

工作事件账本

从录音记录升级为可追溯事件序列，呈现任务、决策、责任、风险和结果如何变化。

创新 02

业务对象语义连接

把个人记忆中的事项关联到企业 CRM、项目、工单、产品和订单，而非停留在摘要。

创新 03

受控资产晋升

建立候选、授权、审核、映射、验证、发布、更新、撤回和审计的完整生命周期。

创新 04

证据与标准双轨

原始记录用于追溯和人类判断；经映射验证的标准数据用于 Agent 运行。

创新 05

可验证工作能力

从重复实践提炼流程、模板和 Skill，由业务责任人验证、版本化和批准。

创新 06

工作过程可观测性

在授权范围内连接任务、决策、等待、返工和结果，识别流程断点与知识缺口。

7.1 本地优先的隐私与边缘理解

在个人设备或受控环境中优先完成采集控制、初步识别、敏感过滤和内容选择；只有必要且获授权的内容才进入企业侧。这样可以减少不必要的数据流动和中心存储压力，同时提升个人对工作记忆的控制力。

8. 典型业务场景

场景 A：会议讨论到项目行动闭环

  1. 会议工具或用户授权设备提供音频、日历和会议上下文。
  2. AI 识别主题、决策、待办、负责人、期限和风险。
  3. 个人查看并纠正识别结果。
  4. 经授权后提交企业侧，关联项目、任务和责任人。
  5. 项目负责人确认，企业 Agent 在权限内更新任务或提醒责任人。
  6. 执行结果和新证据回写项目记录。

验收重点：决策与行动项准确率、项目关联准确率、人工修订率、任务闭环时间。

场景 B：客户需求与产品问题沉淀

从获授权的客户会议、邮件或现场记录中识别诉求，关联 CRM 客户、产品版本和工单；区分客户原话、员工判断和 AI 推断；经业务人员确认后形成需求或问题记录，供企业 Agent 检查重复问题、相关版本和待处理任务。

场景 C：隐性经验转化为组织能力

从多次同类任务中发现重复步骤和判断模式，生成流程或 Skill 候选，由有经验员工和流程负责人验证，再通过小范围试用和结果对比发布版本。新人员复用的是经过验证的流程，不是专家的全部个人记忆。

场景 D：跨系统工作上下文补全

在授权范围内关联日历、会议、钉钉、项目管理、文档和 CRM/ERP 信息，补足单一系统无法表达的上下文，例如任务延期的经确认原因、依赖关系和下一步行动。

9. 设备与产品策略：先验证采集体系，再决定是否自研硬件

9.1 设备不是系统本身

将产品能力拆成采集终端层和统一工作感知服务层。采集终端可以是手机、电脑、会议软件、现有录音卡、耳机或未来自研设备；服务层负责接入、事件理解、个人记忆、语义关联、授权管理、企业连接和 Agent 服务。这样更换设备时，个人工作记忆和企业资产链路不必重做。

方式优点局限 / 风险建议角色
手机普及率高、生态能力丰富录音权限、续航和交互限制第一阶段优先验证
电脑端连接文档、任务和业务系统上下文覆盖不了全部线下场景，需明确屏幕采集边界工作桌面主入口
会议软件会议上下文相对完整只覆盖会议场景正式会议入口
现有录音卡免手持，部分场景操作简单充电、忘带、忘开、数据孤岛和成本需实测对照组 / 补充入口
自研录音设备可按组织需求设计按键、指示、续航、加密和接入硬件研发、认证、供应链和售后成本需求验证后再立项

9.2 自研硬件决策门槛

只有在试点证明免手持、低操作摩擦、稳定采集、可靠同步和组织级管理是明显瓶颈，且现有终端无法满足时，才进入自研硬件立项。评估续航、充电、佩戴舒适度、误触漏录、录制指示、物理暂停、离线缓存、加密、数据导出、生态 API、设备管理和全生命周期成本。

Auday 等现有产品可作为体验与能力对标样本，但应通过实际试用记录功能、数据导出、隐私控制、系统集成和成本，不预设其能力优劣。

10. 验证策略：解决跨人、跨岗位复用难题

10.1 区分三类资产

  • 个人记忆：服务原本人，不以跨人复用为目标。
  • 团队协同资产：经确认的项目决策、状态、任务和共享背景，可在授权团队内使用。
  • 可复用能力资产：从多个实践中抽象、验证和版本化的流程、模板、规则与 Skill，是跨人员复用的主要对象。

10.2 四级验证阶梯

级别验证对象核心问题通过证据
L1 个人有效同一个人能否准确记住上下文并减少整理？检索成功率、纠错率、节省时间
L2 团队协同同一项目团队能否减少遗漏、重复沟通和任务断点？任务闭环、决策追溯、团队确认
L3 岗位复用同类任务、不同人员流程或 Skill 能否帮助新执行者？任务质量、耗时、错误率、专家介入量
L4 跨项目复用相似流程、不同项目能力资产是否有稳定适用范围？多项目验证、适配成本、失败边界

10.3 对照实验

  • 选择一个边界明确、频率较高、结果可观察的流程。
  • 设置现有工具流程基线组与工作感知辅助组。
  • 尽量保持任务难度、时间窗口和人员经验可比。
  • 由业务负责人按统一标准评估结果质量。
  • 统计效率、质量、纠错、人工介入和治理事件。
  • 能力复用测试使用同类任务的新执行者，不复制专家全部个人记忆。

10.4 核心指标

指标组指标说明
采集质量相关工作事件覆盖率抽样真实工作事件中成功捕获并识别的比例
理解质量事件抽取准确率 / 召回率人物、时间、任务和决策识别效果
关联质量业务对象关联准确率项目、客户、产品和工单是否关联正确
记忆质量检索成功率、事实冲突率、纠错率能否找回正确上下文
资产质量企业审核通过率、标准数据验证通过率候选内容能否成为企业可用资产
业务价值任务耗时、遗漏率、返工率、闭环时间是否改善实际工作结果
复用能力新执行者任务质量、适配成本、专家介入量能力资产能否跨人有效
治理质量未授权访问、撤回处理时效、误流转率设置严格安全门槛
经济性单人月成本、单任务成本、节省工时核算硬件、模型、存储、运维和管理成本

指标定义、抽样方法、基线和目标值应在试点前由业务负责人和数据治理负责人共同确认。安全与授权类指标不能用效率收益抵消。

11. 分阶段实施路线

阶段建议周期目标与主要工作阶段门槛
0. 架构与治理准备约 2—4 周选流程、梳理系统和数据对象、确定授权与退出机制、建立事件模型和指标责任、授权、采集范围和退出机制明确
1. 个人工作记忆 MVP约 4—6 周接入现有终端，形成事件、任务、决策和来源引用，提供个人纠错与检索个人持续使用，事件质量与操作摩擦达标
2. 企业业务对象关联约 4—8 周接入一个业务系统，建立对象映射和企业资产审核流程关联准确、审核可执行、授权撤回有效
3. 企业 Agent 业务闭环约 6—10 周选择低风险任务，让 Agent 消费标准数据并回写结果有业务对照证据，权限、审计和回滚有效
4. 能力资产复用与规模化阶段评审后提取流程与 Skill 候选，在新执行者和新项目中受控测试适用范围、版本、兼容性和复用价值得到验证

以上周期为规划估算，不是承诺工期；需根据授权审批、系统接入难度和试点范围调整。真实人员数据采集前必须完成治理与合规评审。

14. 试点验收清单

架构与边界

  • 个人、企业、业务领域中心三级数智底座的责任边界清晰。
  • 工作感知是数据入口和上下文理解能力，不是企业底座本身。
  • 企业数智底座融合既有业务系统、企业知识和协同数据。
  • ADS 不因调度任务而取得个人或企业原始数据所有权。
  • 中心底座提供共同语义、联邦目录和治理能力。

数据与资产

  • 原始信号、工作事件、个人记忆、业务对象、标准数据、证据和能力资产分类清楚。
  • 关键事件保留来源、时间、责任主体和确认状态。
  • AI 推断与人工确认、业务系统事实分开标记。
  • 企业资产转化具有授权、审核、映射、验证和版本流程。
  • 授权撤回、缓存处理、派生数据处理和审计路径经过验证。

产品与业务价值

  • 个人用户可以查看、纠正、检索和管理自己的工作记忆。
  • 工作事件能关联到选定的企业业务对象。
  • 企业 Agent 只消费授权范围内、通过质量验证的标准业务数据。
  • 业务效果通过对照实验或可复核基线验证。
  • 跨人复用验证流程、模板和能力资产，而非复制个人原始记忆。

安全与合规

  • 采集状态明确可见，并支持暂停和退出。
  • 对个人、客户、同事和第三方信息设置必要的敏感处理。
  • 未授权访问和越权写入有阻断、告警与审计。
  • 保留期限、删除、归档和导出规则明确。
  • 适用法律、合同和组织制度完成专项审查。

15. 研究结论与建议

建议将创新主线从“自研录音卡”提升为“多源工作感知—个人工作记忆—业务语义关联—企业资产化—企业 Agent 驱动”的连续能力体系。

  • 个人数智底座：让个人工作过程可理解、可记忆、可检索、可自主控制。
  • 企业数智底座：融合企业自身业务数据与经授权的协同信息，通过领域本体映射和验证形成标准业务数据，驱动企业端口智能体。
  • 业务领域中心数智底座：负责共同语义、联邦资产发现、跨域协同和治理，不集中持有所有原始数据。
  • ADS：在三级底座之间建立共同语义、授权协同、任务调度、审计和能力回馈机制。
近期优先事项：选择一个真实业务流程，完成“个人工作事件生成—业务对象关联—企业审核—标准数据生成—企业 Agent 使用”的最小闭环。在这个闭环得到验证之前，不建议先大规模自研硬件，也不建议先建设全员、全场景的持续采集系统。

## 摘要：不要让用户维护知识库，让系统在正常使用中理解用户

ADS-WORK-08 建立个人、企业和领域之间的共同语义边界；ADS-WORK-09 建立个人事件账本、持续记忆、目标承诺和受约束 Agent 的技术架构。ADS-WORK-10 进一步回答：这些底层能力如何成为普通用户每天能理解、愿意使用并持续获得价值的产品？

**核心判断：个人助理 OS 不应该是一个要求用户持续录入、分类、整理和维护的第二套工作系统，而应该成为连接用户已有设备与应用的个人智能协同层。**

用户继续使用手机、电脑、日历、文档、会议、沟通和任务应用。个人助理 OS 在用户明确授权的范围内理解这些活动，自动形成事件与记忆，帮助识别目标、承诺和下一步，并在适当时机主动服务。只有遇到关键事实、模糊责任、重要权限或高风险动作时，才让用户确认。

### 本专题形成的产品成果

1. Personal Assistant OS 产品定位和设计原则。
2. 面向普通用户的五个核心工作空间与信息架构。
3. 自然感知、自动理解、持续记忆、主动服务、受控执行五个产品闭环。
4. 手机、电脑、Web、语音终端、会议和应用连接器的职责分工。
5. 低打扰的主动服务、每日回顾、承诺提醒和记忆确认交互规范。
6. 新手启用、渐进式授权、隐私控制和记忆纠错体验。
7. Personal Agent 从建议到执行的用户审批体验。
8. MVP 产品路线、试点场景、指标体系和验收标准。

## 1. 产品定位：个人助理 OS 是什么

### 1.1 一句话定义

**Personal Assistant OS 是一个持续理解个人上下文、帮助个人管理重要事情，并在用户授权范围内主动推进任务的个人智能系统。**

它连接个人的设备、应用、数据、记忆和 Agent 能力，但不要求用户放弃现有工具，也不要求用户理解底层本体、Schema、事件流或向量检索。

### 1.2 它不是什么

| 不是 | 原因 |
|---|---|
| 新的个人知识库 | 用户不应该每天手动整理和维护大量资料 |
| 单纯的聊天机器人 | 聊天结束后仍可能失去任务状态、承诺和长期上下文 |
| 第二套任务管理系统 | 不应让用户在多个应用之间重复录入任务 |
| 依赖录音卡的录音产品 | 设备会忘带、没电、未启动，也无法覆盖全部生活与工作场景 |
| 全量个人监控系统 | 个人自主权、透明采集和数据边界是基础约束 |
| 取代所有现有应用的超级 App | 首期应连接既有工具，而不是要求用户迁移全部工作流 |

### 1.3 产品北极星

不是采集了多少小时、沉淀了多少条记忆或连接了多少应用，而是：

> **用户是否更少遗忘重要事情、更快找到需要的信息、更清楚地知道下一步，并且愿意信任系统持续理解自己。**

### 1.4 五个连续产品闭环

1. **自然感知**：从用户主动输入和已授权来源获得上下文。
2. **自动理解**：将零散信息识别为事件、人物、项目、目标、承诺和变化。
3. **持续记忆**：把有长期价值的信息形成可追溯、可纠错的记忆。
4. **主动服务**：发现遗漏、冲突、风险和下一步机会，在适当时机提醒。
5. **受控执行**：准备、推进和执行任务；重要副作用由用户授权。

五个闭环应连续运行，而不是五个互相独立的功能菜单。

## 2. 普通用户体验原则

### 2.1 用户不应该学习系统的复杂性

产品内部可以有本体、事件账本、记忆编译器、授权策略和 Agent Runtime；用户界面不应要求用户理解这些概念。

| 系统内部概念 | 用户看到的语言 |
|---|---|
| Personal Event Ledger | 今天发生了什么 / 时间线 |
| Memory Item | AI 记住了什么 |
| Intent Object | 目标、承诺和待办 |
| Context Package | 我为什么这样建议 |
| Agent Action Proposal | 我准备帮你做什么 |
| Provenance | 这条信息来自哪里 |
| Assertion Status | 已确认 / 需要确认 / 可能过期 |
| Authorization Policy | 哪些内容允许使用、分享或执行 |

### 2.2 十项产品原则

1. **默认自动，关键确认**：日常整理自动完成，重要事实和高风险动作再确认。
2. **不重复录入**：尽可能从用户已经使用的应用获取授权信息。
3. **不要求手动分类**：用户只需说、写、分享或转发，系统负责识别。
4. **先提供价值，再请求更多权限**：用户不连接任何外部来源，也能使用快速记录、对话和回顾。
5. **可解释**：重要提醒、记忆和建议能说明来源及原因。
6. **可纠错**：用户可直接说“不是这样”“这个已经完成”“不要再记住”。
7. **低打扰**：默认汇总，只有真正紧急或时间敏感的事情才打断用户。
8. **跨端连续**：在手机开始的事情，可以在电脑继续；不同设备不重复建档。
9. **个人优先**：个人工作与生活上下文默认由个人控制。
10. **自主程度渐进**：从只读、建议和草稿开始，经过授权再执行。

### 2.3 一个关键判断：不要让用户成为 AI 的数据管理员

用户不应每天处理：
- 给每条内容选择标签；
- 把录音手动归档到项目；
- 为每段聊天填写事件类型；
- 手动维护人物关系图谱；
- 反复复制内容到个人知识库；
- 为每次 AI 记忆更新编写提示词。

系统应该自动做这些工作。用户只在低置信度、高影响或存在冲突时参与确认。

## 3. 产品信息架构：五个核心工作空间

首期建议使用五个核心入口，避免功能过多、学习成本过高。

| 工作空间 | 用户心智 | 核心任务 |
|---|---|---|
| 今日 Today | 今天我需要关注什么？ | 每日简报、变化、优先事项、下一步、待确认 |
| 收集箱 Inbox | 我刚刚记录的东西在哪里？ | 语音、文字、分享、转发、待理解和待确认内容 |
| 时间线 Timeline | 最近发生了什么？ | 工作、生活、学习等事件及其关联 |
| 目标与承诺 Goals | 我正在推进什么？ | 目标、承诺、任务、例程、阻塞和进展 |
| 我的 AI My AI | AI 了解我什么、可以做什么？ | 记忆查看与纠错、数据来源、权限、自动化、隐私控制 |

聊天不是第六个孤立模块，而是全局交互能力：用户可以在任何页面向助理提问、补充背景、纠正记忆或要求执行任务。

### 3.1 今日 Today：默认首页

今日首页不应是信息流或数据仪表盘，而是一个帮助用户做决定的个人驾驶舱。

建议分为：

1. **今天的摘要**：今天的重要变化和整体状态。
2. **接下来**：日程、任务和承诺的时间顺序。
3. **需要关注**：临近截止、未回复、冲突、风险和阻塞。
4. **待我确认**：AI 抽取出的重要候选事实、承诺和记忆。
5. **下一步建议**：最多展示少量高价值建议，并允许忽略。

首页默认不展示所有采集内容，也不要求用户逐条处理。没有重要变化时，应明确告诉用户“今天暂时没有需要特别处理的事项”，而不是为了活跃度制造提醒。

### 3.2 收集箱 Inbox：一个入口接住所有输入

收集箱支持：
- 按住说话或点击录音；
- 文字快速记录；
- 分享文件、网页、图片或文本；
- 转发用户主动选择的邮件或消息；
- 从已授权连接器同步的待处理信息；
- 会议结束后生成的待确认摘要。

系统自动识别类型、来源、时间和可能关联对象。用户不需要选择文件夹、标签或本体类型。

收集箱状态建议：
- 正在处理；
- 已整理；
- 需要确认；
- 已关联目标或项目；
- 失败或需要重新处理。

### 3.3 时间线 Timeline：个人连续上下文

时间线不是把所有原始数据混在一起，而是展示对用户有价值的事件和变化。

支持简单筛选：
- 全部；
- 工作；
- 生活；
- 学习与成长；
- 项目；
- 目标与承诺。

每条事件卡片应说明：发生时间、简要内容、来源、关联对象、确认状态和可用操作。

默认按时间浏览；高级用户可按项目、人物或主题检索。敏感内容默认折叠或隐藏，不在公开通知中暴露。

### 3.4 目标与承诺 Goals：从记住走向推进

重点展示：
- 正在进行的目标；
- 对自己或他人的承诺；
- 当前任务和下一步；
- 已完成和已取消的事项；
- 阻塞、依赖和截止风险。

系统可以从会议、消息和用户输入中识别承诺候选，但只有用户确认或权威任务系统同步后，才将其作为正式承诺。

用户无需维护复杂项目计划；可以用自然语言说“这件事先暂停”“下周再提醒我”“这个已经完成”。

### 3.5 我的 AI My AI：用户控制中心

包含四个简单区域：

- **AI 记住的**：当前长期记忆、来源和确认状态。
- **数据来源**：连接了哪些应用和设备、同步状态、最近采集时间。
- **权限与隐私**：哪些数据可以用于什么目的、分享给谁、保留多久。
- **自动化**：有哪些定时回顾、提醒和已授权任务。

这里不是让用户每天维护记忆，而是提供随时检查、纠正和撤回的控制入口。

## 4. 全局交互：让输入、对话和动作随处可达

### 4.1 全局快速入口

任何页面都应有统一的“告诉助理”入口，支持：
- 说一句话；
- 输入一句话；
- 分享当前内容；
- 询问当前页面中的信息；
- 要求整理、提醒或创建草稿。

用户不需要先判断这段内容属于“事件、任务、知识还是记忆”。系统负责识别，并在必要时提出一个最有价值的确认问题。

### 4.2 对话不是数据孤岛

对话中的重要信息可以在用户授权和策略允许下进入事件账本、记忆和目标对象；但普通闲聊不应全部自动变成长期记忆。

每次沉淀都应能回答：
- 为什么认为这条信息值得记住？
- 来自哪段对话或哪个来源？
- 当前是候选还是已确认？
- 用户如何修改或撤回？

### 4.3 用户控制语言

支持自然语言控制：
- “这个记错了，正确的是……”
- “这件事已经完成。”
- “不要把这条内容记为长期记忆。”
- “这条只在当前项目里使用。”
- “以后工作日早上给我看当天重点。”
- “暂停这个来源的同步。”
- “把这条工作承诺整理成企业任务草稿，先别提交。”

系统需要将这些表达转换成可审计的状态变更，而不是只回复“好的”。

## 5. 多终端产品架构：一个个人助理，多种入口

### 5.1 各终端的职责

| 终端 | 核心角色 | 适合的能力 |
|---|---|---|
| 手机 App | 随身入口和主动提醒中心 | 快速记录、语音、通知、日程、即时确认、设备状态 |
| 电脑客户端 | 深度工作助理 | 文档与会议上下文、任务推进、跨应用操作、草稿和审批 |
| Web 工作台 | 全局管理和复盘 | 时间线、记忆管理、数据来源、授权、目标与自动化 |
| 语音终端/可穿戴设备 | 可选的免手操作入口 | 快速记录、用户主动开启的会议采集、语音问答 |
| 日历、邮件、文档、协作应用 | 信息来源与执行工具 | 授权读取、状态同步、草稿准备和受控写回 |
| 会议系统 | 会议场景入口 | 用户主动启用的转写、摘要、决策候选和行动项 |

### 5.2 不要把专用录音设备作为产品前提

语音设备可以成为有价值的入口，但不能成为个人数智底座的唯一感知来源。

产品必须覆盖这些情况：
- 用户忘记携带设备；
- 设备没电或未启动；
- 会议系统已有用户授权的转写；
- 用户在手机上快速记录；
- 用户在电脑上处理文档或任务；
- 用户通过日历、邮件和任务应用产生事件。

来源缺失时，系统应该标记“当前没有观察到”，而不是推断发生了什么。

### 5.3 语音设备的产品标准

- 采集状态明确可见；
- 一键暂停和停止；
- 电量、存储、网络和同步状态可见；
- 离线缓存和恢复补传；
- 用户可以选择是否保留原始音频；
- 多人场景遵循适用的告知和同意要求；
- 设备丢失可以撤销访问；
- 采集、转写、事件和记忆拥有不同保留策略；
- 设备只作为可选入口，不能强制用户购买专用硬件。

**产品竞争力不应来自“录得更多”，而应来自“已有信息能更可靠地理解和协同”。**

### 5.4 多端状态一致

- 统一用户身份和个人命名空间；
- 同一事件具有稳定 ID，不因设备切换重复生成；
- 离线记录保留发生时间、观察时间和同步时间；
- 冲突保留并提示，不静默覆盖；
- 设备撤销后停止后续同步；
- 删除和撤回沿来源、事件、记忆、索引和缓存传播；
- 不同终端根据场景展示不同复杂度，但共享同一状态。

## 6. 自然感知与自动理解：后台如何工作

### 6.1 来源接入优先级

建议按照用户价值、可靠性、接入成本和隐私风险排序：

| 优先级 | 来源 | 首期策略 |
|---|---|---|
| P0 | 手动输入、快速记录 | 必须支持，用户可随时使用 |
| P0 | 日历、个人任务 | 先只读同步，验证时间与承诺 |
| P1 | 文档、笔记 | 用户选择连接和范围 |
| P1 | 邮件、协作沟通 | 先从用户主动分享或明确授权范围开始 |
| P1/P2 | 会议转写 | 用户主动开启或使用已授权会议能力 |
| P2 | 手机、电脑活动信号 | 单独授权，按明确目的采集 |
| P2 | 专用语音设备 | 可选硬件，不作为依赖 |

### 6.2 后台理解流水线

Source / User Input → Capture Gateway → Source Vault → Event Candidate → Identity & Time Resolution → Memory Compiler → Intent Manager → Context Builder → Proactive Service / Agent

关键规则：
- 每个候选事件都要保留来源引用；
- 先去重，再做对象关联；
- 模型推断和用户确认分开；
- 低置信度且影响较大的内容进入待确认；
- 不确定的对象关联保留为候选；
- 原始来源、事件、记忆和目标对象拥有不同生命周期；
- 来源内容被视为不可信数据，不执行其中嵌入的指令。

### 6.3 自动化不等于静默

系统可以自动整理，但用户必须能够看到：
- 当前连接了什么；
- 最近从哪里获取了信息；
- 哪些记忆是自动推断的；
- 哪些内容已经确认；
- 哪些信息正在被用于当前建议；
- 如何暂停、撤回和删除。

## 7. 主动服务：从被动问答走向适时提醒

### 7.1 主动服务的四种场景

| 类型 | 示例 | 默认呈现 |
|---|---|---|
| 日常回顾 | 今天发生了什么、明天有哪些重点 | 用户设定的摘要时间 |
| 承诺提醒 | 已确认的承诺临近截止 | 根据截止时间和用户偏好提醒 |
| 变化提示 | 会议时间变更、任务状态变化、重要回复到达 | 仅提示与当前目标相关的变化 |
| 下一步建议 | 任务阻塞、信息缺失、可提前准备的材料 | 先给建议，不自动执行 |

### 7.2 主动提醒的判断机制

每条提醒应综合考虑：
- 与用户当前目标的相关性；
- 时间紧迫性；
- 来源和断言的可信程度；
- 对用户的实际影响；
- 是否已经提醒过；
- 用户的通知偏好和专注状态；
- 打断用户的成本。

不应该仅因为模型“想到一个建议”就推送通知。

### 7.3 默认低打扰策略

- 默认以今日摘要和待办汇总为主；
- 时间敏感、确有后果的事项才考虑即时提醒；
- 同一主题的多个变化合并；
- 用户忽略的低价值建议降低后续频率；
- 用户可设置专注时间、安静时段和通知渠道；
- 不通过连续提醒制造焦虑或使用时长；
- 每条建议都可忽略、延后、关闭或反馈不准确。

### 7.4 每日回顾的建议结构

1. 今天最重要的三件事；
2. 今天发生的关键变化；
3. 已完成的承诺和成果；
4. 尚未完成或被阻塞的事项；
5. 明天值得提前准备的事情；
6. 需要用户确认的记忆或行动项。

用户可以只看摘要，也可以展开来源和细节。

---

## 8. 记忆管理体验：让用户看得见、改得动

### 8.1 记忆不需要用户日常维护

系统自动处理：
- 事件抽取；
- 记忆候选生成；
- 重复信息合并；
- 时间和对象关联；
- 过期检测；
- 来源变化监测。

用户主要处理三类问题：
1. 事实不正确；
2. 系统不应该记住；
3. 系统需要确认的重要承诺或偏好。

### 8.2 记忆卡片的最小信息

- AI 当前记住的内容；
- 信息来自哪里；
- 当前状态：已确认 / 自动推断 / 需要复核 / 可能过期；
- 适用范围：个人 / 工作项目 / 仅当前任务；
- 用户操作：确认、修改、暂不使用、撤回或删除。

### 8.3 纠错交互

用户说“我已经不负责这个项目了”时：
1. 找到相关记忆和来源；
2. 展示当前记忆及其影响范围；
3. 询问是否更新为新的有效状态；
4. 新增纠正事件；
5. 更新记忆视图；
6. 刷新相关目标和任务；
7. 不再把旧状态作为当前事实使用。

### 8.4 删除与遗忘

“不要再记住”必须是一个真实的数据控制操作，而不是一句对话回复。

用户可以选择：
- 不保存当前内容；
- 从长期记忆中移除；
- 删除某个来源及其派生内容；
- 暂停某个数据源；
- 关闭某类记忆或某个场景的自动理解。

具体删除范围、保留例外和处理状态需要透明反馈。

## 9. Personal Agent 交互：用户知道 AI 准备做什么

### 9.1 自主程度的产品表达

底层 ADS-WORK-09 保留 L0—L3 风险分级。面向普通用户，可以表达为五种体验状态：

| 产品状态 | 用户看到的体验 | 底层约束 |
|---|---|---|
| 观察 | AI 帮我查看和理解 | L0，只读授权 |
| 建议 | AI 告诉我可以怎么做 | L0/L1 |
| 准备 | AI 帮我写好草稿或计划 | L1，不产生外部副作用 |
| 执行 | AI 按我确认的内容操作 | L2，需要明确审批 |
| 高影响执行 | AI 对外发送、支付、删除或修改权限 | L3，逐次确认及必要的额外验证 |

### 9.2 审批卡片必须清楚

用户批准前必须看清：
- AI 要做什么；
- 操作哪个对象；
- 会发送或修改哪些内容；
- 使用哪个应用或工具；
- 会产生什么影响；
- 是否可以撤销；
- 批准有效期。

不能使用模糊按钮“全部交给 AI”。计划内容变化后，应重新获得确认。

### 9.3 执行后的反馈

执行结束后显示：
- 已完成并核验；
- 部分完成；
- 未完成及原因；
- 需要用户继续处理；
- 已生成的后续事件或任务。

不得把“已提交请求”描述为“已成功完成”。

## 10. 新手启用：一分钟内获得第一个价值

### 10.1 不要一开始要求用户连接全部应用

建议采用渐进式启用：

1. 打开个人助理，先介绍它能帮助用户做什么。
2. 用户可以立即使用文字或语音快速记录。
3. 生成第一个简短的个人回顾或信息整理结果。
4. 再邀请用户选择一个最有价值的数据来源，例如日历。
5. 明确展示授权范围和暂停方式。
6. 用户体验到价值后，再逐步增加文档、任务和会议来源。

任何步骤都应允许跳过。拒绝连接不影响核心的手动记录和对话功能。

### 10.2 首次启用不要问太多问题

不建议要求用户填写职业、岗位、组织、工作习惯、家庭情况、兴趣、目标和偏好等长问卷。

通过实际使用逐步理解：
- 用户主动告诉系统的内容；
- 用户确认的偏好；
- 反复出现且有证据的工作模式；
- 用户愿意连接的应用；
- 用户主动建立的目标和承诺。

对高影响或敏感内容，不通过行为猜测自动固化。

### 10.3 渐进式授权

| 阶段 | 授权方式 | 价值 |
|---|---|---|
| 第一步 | 不连接任何外部应用 | 快速记录和对话 |
| 第二步 | 连接一个只读来源 | 自动形成时间线和每日摘要 |
| 第三步 | 连接更多用户选择的来源 | 补充工作和生活上下文 |
| 第四步 | 开启主动提醒 | 发现承诺和变化 |
| 第五步 | 开启受控 Agent 执行 | 用户批准后推进任务 |

## 12. MVP：先验证用户价值，不先追求完整 OS

### 12.1 第一阶段产品范围

建议首期只实现：

- 手机或 Web 的快速文字/语音记录；
- 一个用户选择的只读来源，例如日历；
- 自动形成个人事件时间线；
- 每日摘要；
- 目标、承诺和待确认候选；
- 记忆查看、纠错和撤回；
- 简单的提醒；
- 对外执行暂不开放，先生成草稿。

首期不必实现：
- 全天候录音；
- 全量电脑活动采集；
- 复杂个人知识图谱编辑；
- 多 Agent 自主协作；
- 自动发送邮件或对外写入；
- 强制更换用户现有应用。

### 12.2 试点场景

| 场景 | 验证目标 |
|---|---|
| 每日工作回顾 | 是否减少手动整理和信息遗漏 |
| 会议承诺识别 | 是否能区分讨论、建议和真实承诺 |
| 多来源时间线 | 是否能关联同一事项的不同来源 |
| 个人目标推进 | 是否能持续提醒下一步而不是只生成摘要 |
| 记忆纠错 | 用户是否能理解和控制 AI 记忆 |
| 语音与快速记录 | 是否比专用录音设备更容易坚持使用 |

### 12.3 产品评估指标

| 维度 | 指标 | 判断方向 |
|---|---|---|
| 使用门槛 | 首次价值时间 | 越短越好 |
| 输入成本 | 单次记录操作耗时 | 尽可能低 |
| 自动化价值 | 自动整理后被用户保留的比例 | 越高越好，但不能鼓励过度采集 |
| 事件质量 | Event Precision / Recall | 按场景评测 |
| 记忆质量 | 用户抽查正确率 | 越高越好 |
| 提醒质量 | 有用提醒率 / 错误提醒率 | 同时衡量正负效果 |
| 推进价值 | 承诺按时完成率、阻塞发现率 | 与基线对比 |
| 信任 | 用户对来源、权限和纠错的理解度 | 持续提升 |
| 打扰程度 | 无用通知、重复通知和关闭率 | 持续下降 |
| 隐私 | 未授权采集或投影次数 | 目标为零 |
| Agent 安全 | 未审批高风险动作次数 | 目标为零 |

不以日活、录音时长、消息数量或记忆条数作为唯一成功指标。

## 13. 实施路线与验收门槛

| 阶段 | 产品交付 | 进入下一阶段的条件 |
|---|---|---|
| P0 产品验证 | 交互原型、用户访谈、核心流程 | 普通用户能理解价值，不需要学习数据模型 |
| P1 快速入口 | 文字/语音记录、收集箱、来源展示 | 记录成本低，来源可追溯 |
| P2 个人时间线 | 事件抽取、关联、每日摘要 | 用户认可时间线的准确性和价值 |
| P3 记忆与承诺 | 记忆查看、确认、纠错、目标和承诺 | 用户能理解和控制 AI 记忆 |
| P4 主动服务 | 每日回顾、承诺提醒、变化提示 | 提醒有用且不造成明显打扰 |
| P5 受控 Agent | 草稿、审批、执行核验 | 权限、审批和审计通过评审 |
| P6 多端协同 | 手机、电脑、Web、语音设备 | 同步、撤销、离线和删除传播可靠 |

### 13.1 首期试点周期建议

以 2—4 周的小范围用户试点为起点：
- 第 1 周：快速记录、来源接入、每日回顾；
- 第 2 周：时间线、记忆确认和承诺识别；
- 第 3 周：提醒质量、纠错和隐私体验；
- 第 4 周：用户访谈、指标复盘和是否进入下一阶段决策。

实际周期根据产品和工程资源调整。

## 14. 建议冻结的产品决策

1. Personal Assistant OS 是个人智能协同层，不是要求用户迁移全部工具的新超级 App。
2. 普通用户只需要理解今日、收集箱、时间线、目标与承诺、我的 AI 五个工作空间。
3. 全局对话和快速记录随处可达，不让聊天成为信息孤岛。
4. 用户不需要理解标签、本体、Schema 和事件类型。
5. 自动整理是默认能力，重要事实、模糊承诺和高风险动作需要确认。
6. 语音设备是可选入口，不能成为个人数智底座的必要条件。
7. 多端共享同一事件和记忆身份，支持离线和冲突处理。
8. 主动服务默认低打扰，以摘要和高价值提醒为主。
9. 记忆可见、可纠错、可撤回、可删除。
10. 个人数据默认个人控制，企业协同通过目的绑定的最小必要授权投影。
11. 首期先做只读、草稿和提醒，不急于开放高影响自动执行。
12. 产品价值以减少遗漏、降低整理成本、提升推进效率和用户信任衡量。

## 15. 本专题结论与下一专题

个人助理 OS 的关键，不是把所有 AI 能力堆到一个界面，而是把个人数智底座的复杂能力隐藏在自然、连续、可信的体验背后。

- 用户只需要记录、表达、查看和确认。
- 系统负责采集授权来源、理解事件、形成记忆和组织目标。
- 助理负责发现重要变化、提出下一步建议。
- Agent 在明确的边界和审批下执行。
- 用户始终拥有查看、纠错、撤回、导出和删除的控制权。

**不要让普通用户学习如何维护数智底座；让数智底座在用户正常使用设备和应用的过程中，自然理解用户、服务用户。**

### 下一专题 ADS-WORK-12

ADS-WORK-11 已用于《PDKS 与 ADS 个人数智底座融合架构》。下一专题建议研究《个人助理 OS 的主动智能、个人上下文预测与长期目标推进机制》。

重点研究：
1. 如何从事件变化中识别用户当前最重要的目标；
2. 如何预测承诺风险、任务阻塞和信息缺口；
3. 如何构建不打扰用户的主动服务策略；
4. 如何从每日回顾走向周度、月度和长期目标复盘；
5. 如何建立个人 Agent 的长期任务记忆和跨任务连续性；
6. 如何评估主动建议的准确性、价值和打扰成本；
7. 如何让个人 Agent 与企业 Agent 在授权边界内协同推进。

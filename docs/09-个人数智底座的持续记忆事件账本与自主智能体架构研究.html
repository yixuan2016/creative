Executive Summary

个人数智底座不是更大的个人知识库

如果 AI 只记住聊天摘要，仍然不知道事情从哪里来、是否被确认、后来是否变化，也不知道下一步要推进什么。个人数智底座必须把记忆和运行结合起来。

架构判断：事件账本、记忆视图、目标承诺、任务上下文和 Agent 行动必须分开建模，再通过来源、身份、时间和授权关系连接。

本专题的六个关键结论

01 / LEDGER

事件账本是入口

每条事件都保留时间、来源、断言状态和纠错关系。

02 / MEMORY

记忆是可纠错视图

候选、确认、冲突、过期和撤回都必须有明确状态。

03 / INTENT

目标与承诺独立建模

记住一件事不等于知道下一步做什么。

04 / CONTEXT

上下文按任务构建

只向模型提供当前任务所需且被授权的信息。

05 / AGENT

Agent 受风险约束

草稿、可逆写入和外部高影响动作使用不同审批门槛。

06 / TRUST

个人拥有控制权

查看、纠正、撤回、导出和删除是基础能力，不是附加功能。

01 · Core Objects

五类对象必须分开：事件、记忆、意图、上下文和行动

Personal Event · 发生了什么？

记录发生、观察、表达或状态变化，保留来源、时间、主体、对象和断言状态。它不一定是已经确认的事实。

对象回答的问题关键约束
Personal Event发生了什么？来源在哪里？来源可追溯、时间可区分、可纠错
Memory Item哪些信息值得未来记住？必须引用来源、置信度、有效期和用户控制
Intent Object用户想实现什么、承诺了什么？确认状态、负责人、期限和下一步
Context Package当前任务需要哪些信息？最小必要、目的绑定、有效期
Agent ActionAgent 准备或执行什么？能力白名单、风险、审批和结果核验
记忆不等于事实；推断不等于确认；建议不等于执行；执行也不等于成功。

03 · Continuous Memory

持续记忆：从事件形成长期理解，而不是堆积摘要

记忆生命周期

Candidate · 候选记忆

模型或规则从事件中抽取出的候选认知。保留来源和置信度，但不能被描述成已确认事实；影响较大的内容应向用户确认。

不能使用“最新一条覆盖旧记忆”或“置信度最高者胜出”。冲突需要保留来源、有效时间和不同断言，无法判断时向用户呈现。

个人 Agent 与企业 Agent 的边界

PERSONAL AGENT

代表个人利益

读取个人授权上下文，帮助个人安排、判断和行动。个人原始记忆由个人控制。

ENTERPRISE AGENT

代表企业业务责任

只读取企业侧授权的业务对象、事件和上下文，不通过派生引用读取个人原始记忆。

06 · Risk & Approval

Agent 自主程度必须与动作风险匹配

L0 · 只读查询

检索、总结和状态查询。在用户已授权的数据范围内可自动执行，并保留来源引用和任务目的。

风险等级典型动作默认控制
L0只读检索、总结、状态查询授权范围内可自动进行
L1生成草稿、建议、个人提醒草案自动准备，用户检查
L2修改个人日历、任务、文件或其他可逆状态执行前明确确认
L3对外发送、支付、删除、公开发布、修改权限逐次明确确认，必要时额外验证
审批必须绑定具体动作：目标对象、具体字段、工具、预期副作用、计划版本、有效期和回滚方案。计划发生实质变化时，必须重新审批。
07 · Capture & Multi-device

多源感知要追求可靠上下文，不是无边界采集

P0

手动记录、日历、任务

用户意图清晰、时间和状态明确，适合首期验证。

P1

文档、笔记、沟通

补充项目背景、协作事件和经验线索。

P2

会议语音、设备信号

作为可选来源，须有清晰告知、授权和暂停能力。

语音采集终端的产品要求

可靠性

录音状态、电量、存储、网络、离线缓存和补传状态可见。

用户控制

一键暂停、停止、删除、同步设置和设备撤销。

数据生命周期

原始音频、转写、事件和记忆分别设置保留期限。

场景合规

多人场景尊重参与者告知和同意要求，不以隐蔽录音作为前提。

本地优先、加密同步、用户可控。云端同步不意味着服务端默认可以读取所有明文；设备丢失时需要撤销设备和保护密钥。

删除和撤回必须沿派生链传播

  1. 停止相关数据新的检索、推断和投影。
  2. 找到依赖该来源的记忆、摘要、索引和缓存。
  3. 按请求和适用规则删除、限制或替换内容。

10 · End-to-end Example

从一句承诺到个人 Agent 协助推进

用户手动记录：“周五前整理项目风险清单并确认责任人。”
  1. 个人事件账本记录承诺事件，保留原始来源、发生时间和记录时间。
  2. 记忆引擎形成一条可追溯的承诺记忆，标注来源和确认状态。
  3. 用户确认后建立 Personal Commitment，包含截止时间和下一步行动。
  4. Agent 建议创建提醒，但动作处于 L2 待审批状态。
  5. 用户批准具体提醒内容和时间后，工具才允许执行。
  6. 执行结果经过核验，新增一条个人事件，更新承诺进展。

11 · Pilot Evaluation

试点衡量上下文帮助与用户控制感，不追求采集数量

Event Precision / Recall

按事件类型评估抽取质量。

Memory Correctness

用户抽查记忆是否准确、有用。

Stale Memory Rate

过期或失效记忆的比例。

Retrieval Utility

检索是否真正帮助当前任务。

Correction Burden

用户纠正和管理记忆的负担。

Approval Bypass

未经审批执行 L2/L3 的次数，目标为零。

所有长期记忆可追溯；候选与确认可区分；纠错和删除可传播；个人生活信息不越界；L2/L3 审批绕过次数为零。

13 · Architecture Decisions

建议冻结的十二项架构决策

ADR建议决策
01个人数智底座以个人为主体，而不是以员工身份为主体。
02事件账本、记忆、意图对象和 Context Package 分离。
03事件采用追加式纠错，删除权仍须落实。
04记忆默认从候选开始，模型不能静默把推断升级为事实。
05长期记忆必须有来源、置信度、有效性和用户控制入口。
06目标、承诺和任务是独立运行对象。
07个人数据默认 personal_only，跨边界必须目的绑定和最小必要授权。
08Personal Agent 使用能力白名单、风险分级和审批门禁。
09L2/L3 动作未获得有效审批前禁止执行。
10Agent 执行结果必须核验并写回事件账本。
11多设备同步采用本地优先和加密边界。
12删除、撤回和抑制必须覆盖派生记忆、索引、缓存和后续重建。
Conclusion & Next Research

让 AI 持续理解人，并在用户允许的范围内帮助推进重要事情

个人数智底座的价值，不在于让 AI 无所不知，而在于让 AI 在用户允许的范围内，可靠地理解重要上下文，并帮助用户把重要事情持续推进。

事件账本

让每一条重要信息可追溯、可纠错。

持续记忆

让 AI 跨时间理解用户，但不把推断当事实。

个人 Agent

让 AI 从建议走向受约束的行动和反馈。

# 个人助理 OS · 30 天试点用户访谈提纲

> ADS-WORK-10.1 配套研究工具 · V0.1  
> 用途：验证产品是否减少整理成本、减少遗漏、提升上下文连续性，并让用户理解和信任权限边界。  
> 说明：所有参与均应自愿、透明告知，可随时退出。访谈不要求参与者提供敏感个人内容。

---

## 1. 研究原则

1. 不把采集量、录音时长或打开次数作为成功指标。
2. 不要求参与者分享私人对话、家庭细节、健康、财务或其他敏感信息。
3. 评估记录使用参与者代号，不记录真实姓名或原始消息正文。
4. 明确区分模拟原型、只读试点和真实数据接入。
5. 任何真实数据源都必须单独授权、说明目的和范围。
6. 参与者可以暂停来源、撤回授权或退出试点。
7. 不把模型推断当成事实；评估时保留用户纠错。
8. 记录产品行为，不对参与者的工作绩效或个人生活作价值判断。

## 2. 试点前访谈（Day 0）

### 当前工作方式
- 你通常通过哪些工具记录重要事情？
- 哪些信息最容易遗漏？
- 你现在如何回顾会议、任务和承诺？
- 你会在什么情况下重复向 AI 解释背景？
- 维护知识库、任务和笔记需要多少时间？

### 价值期待
- 如果个人助理只能先解决一个问题，你希望是什么？
- 什么样的自动整理对你有价值？
- 哪些事情你希望系统绝对不要自动做？

### 信任与控制
- 你如何判断一条记忆是否正确？
- 你希望如何查看来源、纠正和撤回？
- 哪些数据来源你愿意连接？哪些不愿意？
- 什么样的提醒会让你觉得打扰？

## 3. 第 1 周：快速记录与事件理解（Day 1—7）

观察：
- 用户是否能在不分类的情况下快速记录；
- 形成事件时是否能看懂来源；
- AI 是否把讨论误判为承诺；
- 用户是否需要反复编辑或整理。

访谈：
- 哪个入口最自然？
- 哪种内容最容易被系统理解错？
- 你是否知道这条事件从哪里来？
- 形成事件之前，你是否清楚系统准备做什么？

## 4. 第 2 周：记忆与纠错（Day 8—14）

观察：
- 用户是否理解候选与已确认的差别；
- 用户是否能轻松确认、纠正和撤回；
- 纠正后旧版本是否清楚地退出当前上下文；
- 是否出现“系统记住了不应该记住的内容”。

访谈：
- 哪条记忆最有用？为什么？
- 有没有一条记忆让你觉得不准确或不舒服？
- 纠正操作是否容易理解？
- 你是否相信撤回后系统不会继续使用旧信息？

## 5. 第 3 周：目标、承诺与主动提醒（Day 15—21）

观察：
- 系统是否区分建议、讨论和承诺；
- 责任人和截止时间是否可靠；
- 提醒是否在合适时间出现；
- 用户是否可以忽略、延后或关闭提醒。

访谈：
- 哪条提醒真正帮到了你？
- 哪条提醒没有必要？
- 你是否感到被催促或被监控？
- 责任人不明确时，系统的处理是否合理？

## 6. 第 4 周：连续上下文与信任（Day 22—30）

观察：
- 用户是否能回看 30 天的重要变化；
- 记忆是否过期、冲突或重复；
- 用户是否能理解数据来源和授权范围；
- 用户是否理解 Agent 审批不等于执行成功。

访谈：
- 30 天后，系统是否更理解你正在做的事情？
- 哪些事情你不再需要重复解释？
- 哪些地方仍然需要你手工维护？
- 你愿意继续使用吗？需要先改变什么？
- 你是否知道如何暂停来源、撤回记忆和拒绝 Agent 动作？

## 7. 量化记录建议

使用同目录的 \`个人助理OS30天试点评估模板.csv\`。每次只记录抽样判断，不记录原始私人内容。

| 指标 | 记录方式 |
|---|---|
| 事件准确率 | 抽样事件中经用户核验正确的比例 |
| 记忆有用率 | 用户审核后认为有长期价值的比例 |
| 纠错成功率 | 纠正后旧值不再被当作当前事实使用 |
| 承诺识别准确率 | 真实承诺候选中被用户确认正确的比例 |
| 提醒有用率 | 用户评价有帮助的提醒比例 |
| 打扰程度 | 用户对频率、时机和内容的主观评价 |
| 维护耗时 | 用户每周用于整理和纠错的时间 |
| 信任理解度 | 用户能否说清来源、权限、撤回和审批边界 |

## 8. Go / No-Go 建议

进入真实数据源连接前，至少满足：
- 用户能理解授权来源和范围；
- 用户能区分 Event、Memory、Intent 和 Agent Action；
- 候选承诺不会未经确认进入正式状态；
- 用户可以纠错、暂停和撤回；
- 来源撤销和记忆撤回具有明确处理状态；
- 主动提醒的有用性高于打扰成本；
- L2/L3 审批能够被用户正确理解；
- 安全、隐私、业务和法务评审通过。

如果用户不能理解数据流和控制方式，不应通过增加更多功能来掩盖问题。
